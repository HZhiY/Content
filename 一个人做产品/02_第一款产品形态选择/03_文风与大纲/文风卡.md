## 二、全包一句话文风定义

本主题包应采用「手机翻页友好的形态判断笔记体」：从「做产品 = 做 App / 小程序最火」等常见误解切入，用短卡建立「形态 = 触达方式 + 成本组合」地图，各条只答一个形态或一个判断点，语气像开发者给开发者递可截图边界表，不像培训号或暴富导师。

---

## 三、系列继承规则

本文必须继承的系列规则：

1. **生产与发布分离**：主题包一次查资料、一次写母稿；每条图文 500–800 字、6–7 卡，可独立搜索、收藏、发布。
2. **解释边界**：每条只讲一个点；以国内个人开发者场景为主；国外仅作参考系。
3. **气质与姿态**：清楚、克制、真实、可收藏；「我把自己会遇到的问题整理出来」，不承诺收益。
4. **推荐句式**：「很多人以为……」「但真正开始做以后会发现……」「第一款阶段往往……」「关键词不是 A，而是 B」。
5. **风险边界**：不写绕备案、绕审核、马甲包；合规仅信息整理，不作法律建议。

本文不得继承的内容：

1. 不继承主题包 01 的具体事实展开（备案/域名仅 ≤1 句边界引用）；
2. 不继承其他文章的具体标题、比喻、结构链条；
3. 不复用未放行事实。

## 四、全包微调策略

### 4.1 全包入口

- 推荐入口：**误解破冰 + 场景问句**（「X 适合什么产品？」「先做网页还是小程序？」）
- 禁止入口：保姆级开发教程、形态优劣排行榜、「永远不做 App」、暴富时间线

### 4.2 全包主线

- 主线类型：**机制解释型 + 边界判断型**
- 主线说明：E00P0-01——形态不是「高级程度」，是触达 + 成本；01–04 各答一种形态边界；05 四问决策；06–08 验证与复杂度
- 主线风险：8 条口径打架；候选 3 硬边界在多条重复；条目 05 滑向「网页更好」

### 4.3 判断节奏

- **逐步浮出**：前 2 卡破误解，中段给机制/边界表，末卡一句可复述判断
- 全包 E00P0-01 框架：**每条最多 1 句**，禁止 8 次粘贴同段

## 五、平台与手机阅读要求

### 5.1 句子与段落

- 卡片内 8–18 字短句为主；一卡 30–90 字、≤8 行
- 每张卡片 = 一个视觉节拍；抽象判断后须跟机制或场景钉

### 5.2 前 3 卡任务

1. 清楚问题（与标题一致）
2. 打破 1 个常见误解
3. 让读者知道翻完能带走什么（边界表/四问/开关清单）

### 5.3 关键句

- 允许 2–3 句/条，须机制钉之后；例：「做产品 ≠ 做 App」「注册小程序 ≠ 已上线」

## 六、事实与表达红线（全包）

### 6.1 必守口径

| 事实/口径 | 必须怎么写 | 不能怎么写 |
|---|---|---|
| E00P0-01 全包框架 | 触达方式 + 成本权衡；每条 ≤1 句 | 8 次粘贴同段；形态等级论 |
| E0104 网页更新 | 通常自行部署即生效；违规仍可能被处置 | 零监管、完全不用审核 |
| E0203 小程序发布 | 上传 → 审核 → 手动发布 | 写完代码就上线 |
| E0205/E0206 个人小程序 | 无微信认证；类目须查官方清单 | 个人什么都能做；抄类目表 |
| E0302 公众号 | 偏内容触达，非完整产品容器 | 公众号 = 免费小程序 |
| F02 个人服务号 | 可写服务号助手路径 + 能力边界 | 个人永远不能注册服务号；个人 = 企业支付 |
| E0402/E0403 App | 付费计划才能商店分发；自测 ≠ 上架 | 做产品必须做 App |
| E0503 个人支付 | 个人小程序通常无法微信支付 | 暗示个人小程序能收款闭环 |
| E0601/E0602 App 避坑 | 阶段不匹配；成本前置 | 永远不要做 App（B01） |
| E0702/E0703 表单 | 能验证意愿；不能验证复杂使用 | 表单 = 创业成功（B14） |
| E0801 复杂度 | 登录/支付/后台等是开关 | 无出处工时金额对比 |
| 备案（E01P1-04） | 内地服务器一句边界，引用主题包 01 | 备案教程（B11） |
| 费用数字 | 「目前」「约」「以平台为准」 | 写死审核平均 N 天（B08） |

### 6.2 系列禁区（B01–B14 摘要）

1. 绝对化：永远不做 App、默认网站无例外、小程序万能
2. 培训腔：保姆级、十分钟搞定、全网最全
3. 暴富腔：3 天变现、一年 N 款
4. 灰色：马甲包、审核规避
5. 跑题：备案/域名教程、表单字段校验、平台套餐比价

## 七、正面写作规范

1. **一卡一点**：禁止一卡混讲四种形态
2. **贯穿实例**：全包统一虚构产品 `mytool`；网页 `mytool.com`、小程序名等标「示例」
3. **收藏卡**：01–04 至少 1 张「适合 / 不太适合」对照；05 四问各 1 卡；08 列 3–5 个复杂度开关
4. **备案引用**：每条 ≤1 句，对齐主题包 01 已核口径，不展开
5. **条目不重复论证**：见大纲 §1.1 分工矩阵
6. **caption**：100–200 字；补场景与边界；不复制卡片全文；结尾可加「个人开发者视角整理，非法律建议」
