## 三、外部内容约束

### 3.1 必须避开的常见写法

1. **「第一款默认做网站，没有例外」**——忽视微信生态与国内个人主体限制；与条目 02、05 冲突。
2. **「小程序全面优于网页 / 永远不要做 App」**——绝对化；与 D04、X01、系列基调冲突。
3. **变现时间线故事（3 天付费、一年 10 款）**——暴富腔；掩盖审核、主体、支付门槛。
4. **uni-app/Taro 跨端一把梭**——超出 scope；第一款验证期过度工程。
5. **公众号 = 免费小程序替代品**——能力边界不同；触犯 B05。
6. **表单平台套餐比价 / 前端表单校验教程**——条目 07 是需求验证，不是字段校验或营销比价。
7. **备案/域名保姆级教程**——属主题包 01；本篇边界一句。

### 3.2 可以借鉴但必须改造的传播机制

1. **触达方式 + 成本权衡框架（M01）**— 外部常喊「做产品≠做 App」；须落到 E00P0-01 机制，写阶段不匹配不写选型错误。
2. **四问选型（M02）**— 01MVP 勾选式；改造为 E05P1-04 四问卡片，不给唯一标准答案。
3. **适合/不适合边界表（M03）**— 条目 01–04 各一张边界卡；不写全能对比大全。
4. **先轻后重阶段观（M04）**— 用于条目 06、08 收束；附「验证后再加重形态」。
5. **表单验证意愿边界（M05）**— 条目 07 区分报名/留邮箱 vs 复杂交互验证。
6. **复杂度开关（M06）**— 条目 08 列 3–5 个开关，不写十大坑清单。
7. **国内硬边界（M08）**— 个人无微信支付、查类目、备案引用主题包 01。

## 四、候选洞察

### 主题包价值（跨条目，定调整包）

| 项目 | 内容 |
|---|---|
| 核心判断 | 第一款产品的形态选择，本质是在「怎么触达用户」和「开发与维护要花多少成本」之间做权衡；个人开发者更应优先验证「有没有人要」，而不是先选看起来最正式的重形态。 |
| 回答的读者问题 | 我会写代码了，第一款该做成网页、小程序、公众号还是 App？有没有更轻的验证方式？ |
| 关键事实支撑 | E00P0-01；E0701/E0802；总计划暂定逻辑链；事实核查有条件通过 |
| 传播优势 | 建立形态认知地图；降低「做产品=做 App」默认假设；8 条可独立收藏 |
| 结构风险 | 8 条若口径不统一，读者跨条阅读会感到矛盾；须全包共享 E00P0-01 |
| 事实风险 | 低；P0 已放行 |
| 条目分工 | 01–04 各形态边界 → 05 网页 vs 小程序决策 → 06 App 阶段避坑 → 07 表单验证 → 08 复杂度避坑 |

说明：

这是全包锚点。外部内容要么写「默认做网站」，要么写「小程序/App 对比大全」，要么嵌在变现故事里。本主题包的差异在于：用国内个人开发者硬边界（类目、支付、审核、备案边界）+ 验证优先逻辑，把四种形态拆成可独立查阅的判断卡，而不是给一条标准答案路线图。

---

### 候选 1：触达方式 + 成本权衡（推荐·全包主洞察）

| 项目 | 内容 |
|---|---|
| 核心判断 | 网页、小程序、公众号、App 不是「高级程度」的递进，而是不同的触达用户方式；选形态就是在选运行环境、发布流程、能力开放和维护成本的组合。 |
| 回答的读者问题 | 这些形态到底是什么关系？我为什么不能「随便选一个」？ |
| 关键事实支撑 | E00P0-01；E0102/E0202/E0302/E0401；各形态发布机制差异（E0203、E0502、E0402） |
| 与外部常见写法的差异 | 不写形态「等级论」或「首选方案」；用机制维度（在哪运行、怎么更新、有什么硬限制）代替优劣排序 |
| 传播优势 | 纠正「做产品=做 App」；为 8 条提供统一词汇；收藏向框架图潜力 |
| 结构风险 | 若每条重复全包定义会冗余；条目 01–04 各取一维展开即可 |
| 事实风险 | 低 |
| 适合进入传播学分析 | 是 |

说明：

候选 1 是全包骨架。读者带着「App 才是正经产品」或「小程序最火所以先做」的默认假设进来，文章要做的是建立一张地图：每种形态解决的是「怎么触达」，每种形态附带不同的成本结构。这与外部 W01「默认做网站」不矛盾也不相同——我们不预设答案，而是给判断维度。

---

### 候选 2：验证优先，形态后置（推荐·条目 06、07、08 主洞察）

| 项目 | 内容 |
|---|---|
| 核心判断 | 第一款产品的目标通常是验证核心假设，而不是把技术栈做全；表单、轻量网页等更低成本路径，往往比一上来做 App 或堆登录/支付更合适。 |
| 回答的读者问题 | 能不能先不开发完整产品？为什么不要一开始做太复杂？App 为什么常不适合第一款？ |
| 关键事实支撑 | E0701–E0703；E0801–E0802；E0601–E0602；E0503（支付边界） |
| 与外部常见写法的差异 | 不写「永远不做 App」；不写「表单=偷懒」；写阶段不匹配与验证边界 |
| 传播优势 | 直击个人开发者焦虑（想快点上线又怕选错）；与系列核心判断一致 |
| 结构风险 | 条目 06、07、08 若三条重复「做简单点」会疲劳；须各打一个子问题 |
| 事实风险 | 中；MVP 方法论二手来源，边界须写清 |
| 适合进入传播学分析 | 是 |

说明：

候选 2 服务避坑与验证条目。外部 Harries、01MVP 已反复讲 MVP，但常夹 SaaS/出海默认。本包差异在于：把「验证」落到国内可执行路径（表单、静态页、个人小程序限制），并明确 App 是把账号费、双端、商店审核成本前置，而非吓唬人。

---

### 候选 3：国内个人主体硬边界（推荐·条目 02、03、05 辅洞察）

| 项目 | 内容 |
|---|---|
| 核心判断 | 在国内，形态选择不只是技术偏好，还受主体资质、类目、审核、支付和备案规则约束；个人开发者选小程序或收款闭环时，硬边界往往比「会不会写代码」更早卡住。 |
| 回答的读者问题 | 个人做小程序有什么限制？公众号能不能当产品？第一款要收款怎么办？ |
| 关键事实支撑 | E0205/E0206/E0503；E03P1-03/F02；E01P1-04；E00P1-01 |
| 与外部常见写法的差异 | 不写企业双引擎营销；个人服务号写助手路径+能力边界；类目引导查官方不抄表 |
| 传播优势 | 国内差异化强；解释「为什么个人小程序做不了支付」等高频困惑 |
| 结构风险 | 若条目 02–05 每条重复硬边界会啰嗦；全包统一口径、各条取一切面 |
| 事实风险 | 中；F02 个人服务号、F07 群发次数等 P1 待补已有保守写法 |
| 适合进入传播学分析 | 是 |

说明：

候选 3 是国内语境补丁。外部对比表常忽略个人主体限制。对条目 05「网页还是小程序」，E0503（个人无微信支付）往往是比「开发难度」更硬的决策边界。条目 03 须守住「公众号偏内容触达，不是完整产品容器」。

### 候选 4：四问决策框架（推荐·条目 05 主洞察）

| 项目 | 内容 |
|---|---|
| 核心判断 | 网页和小程序没有 universally 的最优解；用四个问题——用户主要在哪、要多快试错、要不要微信支付、能不能等审核——比直接问「哪个更好」更能帮个人开发者做决定。 |
| 回答的读者问题 | 第一款到底先做网页还是小程序？ |
| 关键事实支撑 | E0501–E0503；E05P1-01–E05P1-04；D04 口径待定 |
| 与外部常见写法的差异 | 不给 01MVP 式「默认做网站」或行业文「小程序全面更好」；用问题代替答案 |
| 传播优势 | 决策型收藏；6 卡可一张一问 |
| 结构风险 | 若四问无具体场景锚点，会显得空；每问须配一句国内个人场景 |
| 事实风险 | 低 |
| 适合进入传播学分析 | 是 |

## 六、初步推荐

### 推荐进入后续分析的候选组合

```text
全包主洞察：候选 1（触达方式 + 成本权衡）
条目 01–04 展开：候选 5（各形态适合边界）
条目 05 主洞察：候选 4（四问决策框架）+ 候选 3（国内硬边界切面）
条目 06 主洞察：候选 2（验证优先）+ 候选 1（App 成本前置）
条目 07 主洞察：候选 2（表单验证边界）
条目 08 主洞察：候选 6（复杂度开关）+ 候选 2（MVP 原则）
跨条辅洞察：候选 3（国内硬边界，02/03/05 轻点）
```

推荐理由：

1. **候选 1** 提供全包统一词汇，避免 8 条口径打架；与 E00P0-01 及事实核查放行结论一致。
2. **候选 4** 解决条目 05 外部最易写成一边倒的问题；与 D04、外部 W02 差异化。
3. **候选 2+6** 分拆条目 06/07/08，各答一题，避免三条都在说「做简单点」。
4. **候选 3** 是国内个人开发者差异化核心；F01–F03 已核，可进入正文规划。
5. **候选 5** 与选题池 01–04 标题天然对齐，每条独立可发布。

### 备选候选

```text
无独立备选主轴；候选 5、6 若与主候选合并过紧，可降级为卡片展开方式而非单独洞察名。
```
