# 主题包：网站上线基础设施

## 图文 01｜域名到底是什么？

**类型**：概念科普  
**卡片数**：6  
**核心口径**：域名是 DNS 寻址名称，解决「别人怎么找到你」，不解决「网页内容是什么」；买了域名 ≠ 有了可访问的网站  
**贯穿实例**：虚构产品域名 `mytool.com`；示例 IP `203.0.113.10`（RFC 文档示例网段，非真实服务器）

### 图 1｜封面

域名到底是什么？
买了域名，为什么还打不开？

### 图 2｜破误解

很多人以为买了域名就有了网站。
比如你花年费注册 `mytool.com`，浏览器却提示无法访问——域名只是名字，网页文件还在服务器上。

### 图 3｜寻址名定义

拿 `mytool.com` 举例：它是给人记的寻址名，不是网站本身。
DNS 负责把它翻译成 IP（示例：`203.0.113.10`），浏览器才能找到那台机器。

### 图 4｜三句话分工

还是 `mytool.com` 这一条链：
`203.0.113.10` → 给机器看的数字地址
`mytool.com` → 给人记的名字
DNS → 把名字翻译成 IP

### 图 5｜访问链路

浏览器输入 `mytool.com`
→ DNS 查到 `203.0.113.10`
→ 连上那台服务器 → 返回网页
光有域名不够，还要解析指向服务器，服务器上也要有页面

### 图 6｜收束

`mytool.com` 在国内还要单独实名，和腾讯云账号实名不是一回事。
域名帮别人找到你，不替你放网页内容。
搞清这一步，才算摸上线地图第一格。

### caption

场景：你刚注册 `mytool.com`，打开却是空白——通常是域名、解析、服务器、页面四件事没串起来，不是「买错了」。备案和买域名也是两回事；实名审核常见约 1–3 个工作日。DNS 怎么配、服务器放哪，见后续条目。个人开发者视角整理，非法律建议。#个人开发者 #独立开发 #产品上线

## 图文 02｜服务器到底是什么？

**类型**：概念科普  
**卡片数**：6  
**核心口径**：服务器是持续运行、对外提供网页或接口的计算机环境；域名指路，服务器放内容、做响应  
**贯穿实例**：`mytool.com` → `203.0.113.10`（示例）

### 图 1｜封面

服务器到底是什么？
有了域名，网页文件放哪儿？

### 图 2｜破误解

很多人把服务器当成域名，或当成网盘。
`mytool.com` 只是寻址名；真正存放 HTML、图片、接口程序的，是 IP 为 `203.0.113.10`（示例）的那台机器。

### 图 3｜一句话解释

服务器是互联网上持续运行、能对外提供网页或接口的计算机环境。
云厂商的「轻量服务器」「云服务器」，本质是远程租一台机器，让你的产品能 24 小时在线响应访问。

### 图 4｜它解决什么

服务器解决「内容存在哪、谁来响应请求」。
浏览器连到 `203.0.113.10` 后，这台机器才返回 `mytool.com` 对应的页面或数据。
没有服务器，域名再漂亮也找不到东西。

### 图 5｜个人开发者要记住

代码在本机能跑通之后，就要想：别人怎么访问。
做第一款小产品时，通常得买或租服务器，把页面部署上去。
服务器和域名是两件独立的事，先有机房再放货。

### 图 6｜收束

记住分工：`mytool.com` 负责指路，`203.0.113.10` 负责开门迎客。
服务器不是 DNS，也不是备案。
搞清服务器，是上线地图第二格。

### caption

场景：域名已注册、代码写好了，却不知道怎么让别人打开——多半卡在「还没买服务器」或「文件没部署上去」。轻量服务器和静态托管怎么选，见条目 09、10。个人开发者视角整理，非法律建议。#个人开发者 #独立开发 #服务器

## 图文 03｜备案到底是什么？

**类型**：概念科普  
**卡片数**：6  
**核心口径**：ICP 备案是用中国大陆服务器对外提供互联网信息服务前的行政登记；不是买域名，也不是技术配置  
**贯穿实例**：`mytool.com` 解析到内地服务器时触发备案场景

### 图 1｜封面

备案到底是什么？
买了域名，为什么还要备案？

### 图 2｜破误解

很多人把备案当成买域名，或当成「给网站加密」。
备案全称 ICP 备案，是在国内服务器上线前的行政登记——和域名注册、SSL 证书是三件不同的事。

### 图 3｜一句话解释

备案解决「这台内地服务器能不能合法对外提供信息服务」。
你把 `mytool.com` 解析到中国大陆的服务器 IP，通常就要在接入商平台提交 ICP 备案。
它是合规流程，不是写代码的步骤。

### 图 4｜它解决什么

备案让监管部门和接入商能核验：谁在用哪台服务器、提供什么服务。
个人备案时，域名实名信息须和备案主体一致。
备案通过后，内地服务器才可持续对外提供服务。

### 图 5｜个人开发者要记住

备案和买域名是两件事，先后遇到，不是一次办完。
备案前通常须先有已实名的域名；刚实名完立刻提交，常见建议等约 3 天再备。
管局审核通常约数个工作日到约三周，以平台进度为准。

### 图 6｜收束

备案不是技术门槛，是内地服务器的合规前置。
关键看服务器在哪里，不是看 `mytool.com` 后缀是不是 .com。
搞清备案，是上线地图里独立的一格。

### caption

场景：服务器买好了、域名也实名了，控制台却提示「未备案」——说明你还差行政登记这一步。不是「.com 就不用备」，关键看解析是否指向内地 IP。个人开发者视角整理，非法律建议。#个人开发者 #ICP备案 #产品上线

## 图文 04｜SSL 证书到底是什么？

**类型**：概念科普  
**卡片数**：6  
**核心口径**：SSL 证书让网站走 HTTPS，加密传输并证明站点身份；解决「路上安不安全」，不解决「内容放哪」  
**贯穿实例**：访问 `https://mytool.com` 时的加密链路

### 图 1｜封面

SSL 证书到底是什么？
网站为什么显示「不安全」？

### 图 2｜破误解

很多人把 SSL 当成备案，或当成域名自带的功能。
SSL 证书只管浏览器和服务器之间的加密传输——和域名注册、ICP 备案、服务器选购各管一段。

### 图 3｜一句话解释

SSL 证书是一份数字凭证，让 `mytool.com` 能用 HTTPS 访问。
浏览器地址栏的小锁，表示你和 `203.0.113.10`（示例）之间的数据被加密，不易被中途窃听或篡改。

### 图 4｜它解决什么

SSL 解决「传输路上安不安全、访客敢不敢输入信息」。
没有证书，浏览器可能标「不安全」，用户填邮箱或密码时会犹豫。
它不负责放网页，也不替代备案。

### 图 5｜个人开发者要记住

第一款产品上线时，HTTPS 几乎是标配——哪怕只是落地页。
云厂商和 Let's Encrypt 等渠道可申请免费或低价证书，但「申请」和「装到服务器」是两步。
证书有有效期，到期前要记得续。

### 图 6｜收束

分工记一句：域名指路，服务器放内容，SSL 护住传输路。
`https://mytool.com` 能打开小锁，不代表已备案、也不代表已部署好页面。
搞清 SSL，是上线地图里安全那一格。

### caption

场景：本地 `localhost` 能访问，上线后浏览器却警告「不安全」——多半是还没配 HTTPS。免费证书怎么申请属操作细节，本篇只讲「它是什么」。个人开发者视角整理，非法律建议。#个人开发者 #HTTPS #SSL证书

## 图文 05｜CDN 到底是什么？

**类型**：概念科普  
**卡片数**：6  
**核心口径**：CDN 把静态内容缓存到离用户更近的节点，加速访问；源站仍是你的服务器，不是替代品  
**贯穿实例**：`mytool.com` 的图片/CSS 从边缘节点返回，源站在 `203.0.113.10`（示例）

### 图 1｜封面

CDN 到底是什么？
已经上线了，还要 CDN 吗？

### 图 2｜破误解

很多人把 CDN 当成服务器，或当成「再买一个域名」。
CDN 是内容分发网络——在你原有服务器（源站）前面加一层缓存加速，不是替代 `203.0.113.10` 那台机器。

### 图 3｜一句话解释

CDN 在全国或全球部署边缘节点，把 `mytool.com` 的静态文件（图片、CSS、JS）复制一份放在离访客更近的地方。
用户访问时，往往从最近的节点取文件，不用每次都跨城连源站。

### 图 4｜它解决什么

CDN 解决「访客离服务器太远、打开慢」。
源站仍是 `203.0.113.10`，CDN 只缓存可缓存的静态资源。
动态接口、数据库读写仍回源站处理。

### 图 5｜个人开发者要记住

第一款小产品、访客不多时，CDN 通常不是第一天必选项。
页面变慢、图片变大、用户分布变广后再考虑，性价比更高。
上了 CDN，`mytool.com` 解析到的 IP 可能变成 CDN 节点，属正常现象。

### 图 6｜收束

CDN 是加速器，不是主机。
记住：源站在 `203.0.113.10`，CDN 在路途上帮一把。
搞清 CDN，是上线地图里「可选优化」那一格。

### caption

场景：朋友在外地打开 `mytool.com` 很慢，本地却很快——可能是源站距离远，CDN 能改善静态资源加载。第一篇产品不必强上 CDN。个人开发者视角整理，非法律建议。#个人开发者 #CDN #网站加速

## 图文 06｜域名、服务器、备案是什么关系？

**类型**：流程认知  
**卡片数**：7  
**核心口径**：域名指路、服务器放内容、备案管内地服务器合规；三者串联但各办各的事  
**贯穿实例**：`mytool.com` → DNS → `203.0.113.10` → 内地服务器需备案

### 图 1｜封面

域名、服务器、备案
到底是什么关系？

### 图 2｜一句话对照

拿 `mytool.com` 串起来：
域名 → 别人怎么找到你
服务器（`203.0.113.10` 示例）→ 内容放哪、谁来响应
备案 → 内地服务器能不能合法对外服务

### 图 3｜域名这一环

你先注册 `mytool.com`，完成实名。
它是名字，不是网站，也不等于已备案。
还要 DNS 解析，把名字指到服务器 IP。

### 图 4｜服务器这一环

再买或租服务器，把页面部署到 `203.0.113.10`（示例）。
服务器在境外，域名可以解析过去，合规场景不同。
服务器在内地，通常进入备案这一环。

### 图 5｜备案这一环

备案不跟着域名走，跟着「内地服务器 + 对外服务」走。
须用已实名且信息一致的 `mytool.com` 提交。
通过后，内地 IP 才能持续对外提供访问。

### 图 6｜串成一条线

典型内地路径：
买域名 → 实名 → 买内地服务器 → 部署 → 备案 → 解析指向 `203.0.113.10` → 访客输入 `mytool.com` 能打开
任一步缺了，都可能卡住。

### 图 7｜收束

三者不是一件事，但上线时会先后遇到。
域名找路，服务器待客，备案给内地服务器发「通行证」。
搞清关系，比死记名词更有用。

### caption

场景：控制台同时提示「域名未解析」「服务器未备案」——说明三件事要分别推进，不能混成一步。审核通常约数个工作日，以平台为准。个人开发者视角整理，非法律建议。#个人开发者 #域名 #备案 #服务器

## 图文 07｜为什么国内服务器通常要备案？

**类型**：概念科普  
**卡片数**：6  
**核心口径**：内地服务器对外提供互联网信息服务，法规要求 ICP 备案；判断关键是服务器位置，不是域名后缀  
**贯穿实例**：`mytool.com` 解析到内地 IP 即触发

### 图 1｜封面

为什么国内服务器
通常要备案？

### 图 2｜破误解

很多人以为「买了 .com 就不用备」，或以为「小网站没人管」。
备案看的是 `mytool.com` 是否解析到中国大陆服务器，与后缀、访问量无必然对应。

### 图 3｜法规在管什么

《非经营性互联网信息服务备案管理办法》要求：
在中国内地服务器提供互联网信息服务，须先备案。
目的是可追溯：谁、用什么域名、在哪台服务器上提供服务。

### 图 4｜为什么个人开发者会碰到

你用内地轻量服务器部署 `mytool.com`，哪怕只是落地页或 API，只要对外可访问，通常就要备。
不是技术考试，是接入商和管局的合规流程。
个人备案时，域名持有者须为本人（工信部 264 号文第一条第一款）。

### 图 5｜和境外服务器的区别

服务器在境外，适用另一套合规场景，本篇不展开。
很多困惑来自：教程用境外主机，自己却买了内地服务器。
选型时先想清楚服务器放哪，备案需求自然不同。

### 图 6｜收束

备案不是域名注册的附赠品，是内地服务器的入场登记。
`mytool.com` + 内地 `203.0.113.10`，通常就要面对它。
搞清原因，比找捷径更省心。

### caption

场景：已买内地服务器，不确定要不要备——只要域名解析到内地 IP 对外服务，通常就要。不写规避路径，只讲为什么存在这道关卡。个人开发者视角整理，非法律建议。#个人开发者 #ICP备案 #合规

## 图文 08｜一个网页上线要经过哪几步？

**类型**：流程拆解  
**卡片数**：7  
**核心口径**：上线是域名、部署、解析、安全、合规等多步串联；不是买域名或写完代码即完成  
**贯穿实例**：`mytool.com` 从注册到可访问的完整路径

### 图 1｜封面

一个网页上线
要经过哪几步？

### 图 2｜为什么不是一步

很多人以为「代码写完 = 上线」或「买了域名 = 能访问」。
以 `mytool.com` 为例，至少要把名字、机器、内容、通路四件事串起来。

### 图 3｜第一步：域名与实名

注册 `mytool.com`，完成域名实名。
实名审核常见约 1–3 个工作日。
这一步只拿到名字，还没有可访问的网站。

### 图 4｜第二步：服务器与部署

买或租服务器（如 `203.0.113.10` 示例），把网页文件或程序部署上去。
先在服务器上能直接通过 IP 访问，再谈域名。
本地能跑 ≠ 别人能访问。

### 图 5｜第三步：解析与 HTTPS

在 DNS 把 `mytool.com` 指到 `203.0.113.10`。
配置 SSL，让访客走 `https://mytool.com`。
解析生效通常需要一些时间传播，以实际查询为准。

### 图 6｜第四步：备案（如适用）

服务器在内地，通常还要 ICP 备案，审核常见约数个工作日到约三周。
备案和解析可并行准备，但内地服务器未备案可能被拦截访问。
境外服务器适用不同合规场景。

### 图 7｜收束

上线 checklist：
域名实名 → 部署到服务器 → DNS 解析 → HTTPS → 内地备案（如需要）
`mytool.com` 能稳定打开，才算真正进入真实世界。

### caption

场景：第一款产品从 demo 到公网访问，按上面顺序自查缺哪环。常见卡点不是代码，而是解析没生效或备案未完成。个人开发者视角整理，非法律建议。#个人开发者 #产品上线 #网站部署

## 图文 09｜静态网站适合什么项目？

**类型**：选择建议  
**卡片数**：7  
**核心口径**：静态网站是预先生成的 HTML/CSS/JS 文件，无需服务器端动态运算；适合展示型、内容固定的小产品  
**贯穿实例**：`mytool.com` 产品落地页、文档站

### 图 1｜封面

静态网站适合
什么项目？

### 图 2｜常见误解

很多人以为「做网站 = 必须买服务器跑后端」。
其实一整个 `mytool.com` 落地页，可以只是一组静态文件，不一定要常驻运行的数据库和接口。

### 图 3｜静态是什么

静态网站 = 事先写好的 HTML、CSS、JS 文件，访客请求时原样返回。
不需要服务器每次现算页面。
部署后可通过 `203.0.113.10`（示例）或静态托管平台对外提供。

### 图 4｜适合什么

适合：`mytool.com` 产品介绍页、个人作品集、活动页、文档站、等待列表。
内容更新不频繁、交互以展示和表单提交为主。
第一款产品验证想法时，静态往往够用且成本低。

### 图 5｜不适合什么

不适合：复杂登录体系、实时协作、大量后端逻辑、频繁读写数据库。
若 `mytool.com` 需要用户账号、付费、动态推荐，通常要后端或 BaaS 支撑。
别为了「显得专业」强行上全栈。

### 图 6｜怎么选

问自己：页面内容是不是能预先生成？用户要不要登录和付费？
若是展示 + 外链表单，静态优先。
若要接口和数据库，看条目 10 轻量服务器。

### 图 7｜收束

静态不是「低级」，是「够用的形态」。
`mytool.com` 第一天只是落地页，静态完全合理。
需求涨了再升级，别第一天过度工程。

### caption

场景：第一款产品只有介绍页和「加入等待列表」按钮——静态托管或对象存储 + CDN 往往就够。内地托管仍可能涉及备案，关键看解析到哪。个人开发者视角整理，非法律建议。#个人开发者 #静态网站 #产品选型

## 图文 10｜轻量服务器适合什么项目？

**类型**：选择建议  
**卡片数**：7  
**核心口径**：轻量服务器是云厂商入门级虚拟机，适合需要后端、数据库或自定义运行环境的小产品；比静态托管多运维，比高配服务器便宜  
**贯穿实例**：`mytool.com` API 与后端跑在 `203.0.113.10`（示例）

### 图 1｜封面

轻量服务器适合

### 图 2｜常见误解

很多人第一天就买服务器，结果只放几个 HTML 文件。
也有人以为轻量服务器 = 域名或 = 备案本身——它只是你租的一台小机器，如 `203.0.113.10`（示例）。

### 图 3｜轻量是什么

轻量应用服务器是云厂商的入门级 VPS：有独立 IP、能装运行环境、自己管部署。
比静态托管灵活，比高配云服务器便宜。
适合个人开发者第一款需要后端的产品。

### 图 4｜适合什么

适合：`mytool.com` 要带 Node/Python 接口、Webhook、小数据库、定时任务。
用户要登录、要 CRUD、要服务端校验，轻量服务器是常见起点。
AI 写的全栈 demo 上线，往往落在这里。

### 图 5｜不适合什么

不适合：纯展示落地页（见条目 09 静态方案）、高并发大流量、复杂微服务。
日活几百以内的小产品，轻量通常够用；别第一天按「百万用户」选型。

### 图 6｜要付出的成本

比静态多：系统更新、安全补丁、进程守护、日志和备份。
服务器在内地，`mytool.com` 通常还要备案。
运维时间也是产品成本，一个人做要算进去。

### 图 7｜收束

轻量服务器解决「我要跑自己的程序」。
`mytool.com` 解析到 `203.0.113.10`，后端和数据库可以都在这台机器上。
静态能搞定就别硬上；真需要后端，轻量是现实起点。
