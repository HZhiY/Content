## 二、方向主承诺

### 2.1 一句话主承诺

```text
域名是 DNS 分层命名体系中的寻址名称——它解决「别人怎么找到你」，不解决「网页内容是什么」；买了域名不等于有了可访问的网站。
```

### 2.2 主承诺拆解

| 位置 | 可以承诺什么 | 必须避免什么 |
|---|---|---|
| 标题 | 「域名到底是什么？」问句；「买了域名为什么还打不开」处境钩；「域名≠网站」纠偏 | 保姆级建站、免备案攻略、全流程上线、选错后缀焦虑、十分钟搞定 |
| 开头 | 从「域名=网站地址 / 买了就能访问」的常见误解切入；用真实处境（注册后空白页）建立问题感 | 先抛 RFC 术语；一上来列「十大坑」；暗示本篇覆盖 DNS/服务器/备案全貌 |
| 正文 | 证明寻址名称 ≠ 内容托管；IP/域名/DNS 三句话分工；访问链路（域名→DNS→IP→服务器→网页）；注册只是第一步（E0106） | 写 DNS 配置步骤；展开备案/续费/后缀流程；写死促销价或审核天数；门牌号单飞不写机制钉 |
| 结尾 | 收束到一句可复述判断；轻点国内「名字资产 + 实名」边界（候选 2）；一句引出主题包后续条目 | 贩卖「还有很多要学」焦虑；暗示本篇已教会上线全流程；结尾拔高到备案/服务器机制详解 |

### 2.3 主承诺成立条件

1. **事实条件**：E0101–E0106 全部 P0 放行；机制表述以 RFC 1034/1035 + 腾讯云《域名简介》为准；遵守 B01–B10 禁止写法。
2. **结构条件**：6 卡沿机制链推进（误解破冰 → 寻址名定义 → 分工 → 链路 → 买了≠能访问 → 国内轻点 → 收束）；每张卡 30–90 字，总 500–800 字。
3. **传播条件**：至少一张可截图收藏的分工图或误解对照；门牌号类比后同卡或下一卡出现 DNS + 服务器钉；读者未读主题包其他条目也能独立带走判断。

### 3.1 洞察组合逻辑

读者从「域名=网站 / 买了就能开」的熟悉误解进入（入口 + 反差），骨架命题用「寻址名 ≠ 网站本体」建立正向定义。副洞察 1（三句话分工）和副洞察 2（访问链路）把「为什么打不开」答成可复述的机制链，而非口号。新意洞察在中段释放「DNS 分层命名 + 寻址与内容分离」，让读者从「知道网址」升级到「知道分工」。结尾先用候选 2 轻点国内「名字资产」边界（账号实名≠域名实名），再用主题包价值一句引出「DNS/服务器/备案是什么关系」后续条目——全部服务同一主承诺：让读者明白域名是什么、不是什么、买了之后还差什么，而不展开全流程或注册教程。

### 3.2 洞察轻重关系

| 内容 | 权重 | 原因 |
|---|---|---|
| 候选 1：寻址名，不是网站本体 | **主线** | 全文结构命题；6 卡主轴 |
| IP/域名/DNS 三句话分工 | **半展开** | 收藏卡核心；1 卡承载 |
| 访问链路四步 | **半展开** | 机制链必要环节；1 卡承载 |
| 买了域名≠能访问（E0106） | **半展开** | 反差兑现；1 卡 |
| 候选 2：双重身份 / 名字资产 | **轻点** | 国内差异化；限 1 卡 |
| 候选 3：概念混淆 | **只作过渡** | 嵌入候选 2 卡内 1–2 条误解对照，不单列 |
| 主题包价值 | **只作过渡** | 末卡或 caption 一句系列钩子 |
| 备案/续费/后缀/DNS 配置 | **不使用** | 超出条目 01 scope；留给后续条目 |

### 6.1 方向判断

当前文章**主要服务**前四类目标客户（有基础编程能力或 AI 写代码、准备上线的中国个人开发者）。非技术读者可接住，但大纲阶段须控制术语密度——每张卡首次出现 DNS/IP/解析须一句人话翻译。**不适合**运维查 DNS 配置者、域名炒卖/SEO 运营者、企业 IT 采购者——他们会被「是什么」科普失望，应被条目 scope 自然过滤。

### 6.2 目标客户不匹配风险

- 风险 1：非技术读者在 DNS/IP 术语处掉线——大纲须首次出现即翻译；不足以阻止进入文风卡和大纲。
- 风险 2：已注册域名卡在排错阶段的读者期待「怎么配解析」——条目 01 只能边界提示，caption 可轻点「DNS 怎么配见后续条目」——不足以阻止进入文风卡和大纲。

说明：候选 2、候选 3 **不放弃为传播/结构素材**；仅放弃其作为条目 01 **主洞察/全文结构命题**的资格。候选 3 拆散嵌入候选 1/2 后可保留 1 张误解对照卡素材。

## 十、给文风卡的指令

文风卡必须把上述洞察组合转译成表达策略，但不得改写方向主承诺。

| 项目 | 文风卡需要处理的问题 |
|---|---|
| 入口洞察表达 | 封面/第 1 卡用「买了域名为什么还打不开」或「域名≠网站」低门槛进入；避免先抛 RFC |
| 骨架命题表达 | 用「域名解决找到你，不解决内容是什么」人话压机制；门牌号后同卡或下一卡补 DNS + 服务器 |
| 副洞察轻重 | 三句话分工、访问链路半展开各 1 卡；候选 2 轻点 1 卡；候选 3 不单独成卡 |
| 新意释放 | 「DNS 分层命名」在第 2–3 卡，须在门牌号/网址桥接之后 |
| 反差控制 | 「买了域名≠有了网站」服务理解，不用震惊体；E0106 作机制钉 |
| 结尾升维 | 可升到「名字资产 + 系列地图一句」；不能升到备案/服务器机制详解 |
| 读者门槛 | DNS/IP/解析首次出现须一句人话翻译；非技术读者术语密度控制 |

### 10.1 文风卡必须避免

1. 把方向把控重新改成另一套主承诺（如「上线全景」或「怎么买域名」）；
2. 为了表达好看而改变事实边界（写死价格、天数、误引 264 号文）；
3. 把候选 2/3 写成新主线；
4. 过早释放「DNS 分层命名」新意而无门牌号桥接；
5. 结尾拔高超过正文证明范围（备案全流程、DNS 配置教程）。

## 十一、给大纲编辑的指令

### 11.1 大纲必须围绕

```text
域名是 DNS 分层命名体系中的寻址名称，解决「别人怎么找到你」，不解决「网页内容是什么」；买了域名 ≠ 有了可访问的网站。
```

### 11.2 大纲必须体现的洞察分工

1. 入口洞察（「买了为什么打不开」/ 域名≠网站）只负责进入，不得直接替代骨架命题；
2. 骨架命题（寻址名 ≠ 网站本体）必须成为 6 卡正文主线；
3. 副洞察（三句话分工、访问链路）只能服务主线，不得开 DNS 配置新主题；
4. 新意洞察（分层命名）必须在门牌号桥接后的第 2–3 卡出现；
5. 结尾升维（候选 2 名字资产 + 主题包一句）必须由正文机制链自然推出；
6. 放弃项（备案流程、后缀选购、续费详解、DNS 配置、避坑清单）不得进入大纲。

### 11.3 大纲必须避免

1. 6 卡变「上线基础设施全景」或「域名注册保姆级教程」；
2. 门牌号类比后无 DNS/服务器机制钉（B04 风险）；
3. 候选 2 实名内容超过 1 卡或写注册步骤；
4. 候选 3 独立成「十大误区」清单卡；
5. 与条目 06「域名、服务器、备案是什么关系」重复展开三者关系。

### 11.4 大纲失败信号

如果大纲出现以下情况，应判定失败：

1. 标题入口和正文证明方向不一致（问「是什么」写「怎么买」）；
2. 入口洞察替代了骨架命题（全文只纠偏不定义）；
3. 副洞察抢主线（实名/备案占 3 卡以上）；
4. 多个洞察被并列堆放，没有共同服务主承诺；
5. 结构命题无法被 E0101–E0106 事实证明；
6. 非技术读者读不懂（DNS/IP 无翻译）或查操作者失望（无配置步骤却标题暗示）；
7. 只是复述材料，没有形成机制解释链；
8. 过度照搬外部 W01 门牌号单飞或 T04 避坑清单；
9. 违反系列基调（暴富/培训号/灰色规避）或 B01–B10；
10. 超出事实核查清单放行范围或使用 G01/G02 待补项作核心支点。

## 十二、最终提醒

1. **条目 01 只打一个点**：域名是什么、不是什么；买了之后还差什么——不展开 DNS 配置、备案流程、后缀选购。
2. **门牌号不是终点**：凡出现门牌号，同卡或下一卡必须有 DNS 翻译 + 「内容在服务器」机制钉。
3. **候选 1 唯一主轴**：候选 2 限 1 卡国内边界；候选 3 拆散嵌入；主题包价值末句一句。
4. **事实口径守死**：P0 以 RFC 1034/1035 + 腾讯云《域名简介》为准；审核/宽限期带「通常」「约」；264 号文引用第一条第一款。
5. **6 卡独立成立**：读者未读主题包其他 9 条也能读完并带走「域名是寻址名，不是网站」判断。
6. **收藏卡硬性要求**：至少一张可截图的分工图（IP/域名/DNS）或「域名是什么 / 不是什么」对照。
