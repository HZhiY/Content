## 一、本文结构命题前提

### 1.1 当前文章表面题材

主题包「网站上线基础设施」：面向中国个人开发者，整理网站上线所需的基础设施概念（域名、DNS、服务器、备案、SSL、CDN 等）。

**试水 scope**：仅条目 01「域名到底是什么？」——概念科普类单条小红书图文（6 张卡片 + caption，500-800 字）。

### 1.2 当前文章真正要解释的问题

**主题包层**：一个中国个人开发者要把网站上线，域名、DNS、服务器、备案、SSL、CDN 之间是什么关系？

**条目 01 层**：域名到底是什么？它和网站、IP、DNS 分别是什么关系？个人开发者为什么要在意它？

表面在讲「域名」这一个词；真正要解释的是：**域名是 DNS 分层命名体系中的寻址名称，解决「别人怎么找到你」，不等于网站本身，也不等于买了就能访问。**

### 1.3 当前文章读者已有认知

依据读者画像与总计划，目标客户通常：

- 会写代码，做过网页或小程序，但不知道完整上线流程；
- 听过「域名」「服务器」「备案」，但不清楚三者分工与先后关系；
- 可能以为「买了域名 = 有了网站 = 能打开访问」；
- 知道要花钱注册域名，但不理解 DNS、IP、解析在其中的位置；
- 不想听暴富故事，只想知道「会卡在哪里、要记住什么」。

### 1.4 当前文章应提供的新启发

读者读完条目 01 后，应能复述并带走：

1. **概念澄清**：域名不是网站本身，更像「门牌号 / 访问入口」；
2. **分工认知**：IP 给机器看，域名给人记，DNS 负责把域名翻译成 IP；
3. **机制认知**：访问链路是「输入域名 → DNS 查询得 IP → 连接服务器 → 返回网页」；
4. **行动提醒**：注册域名只是第一步，还要解析、服务器和实际内容；国内服务器场景下备案是另一道关卡（仅边界提示，不展开流程）；
5. **可收藏框架**：一张能截图保存的「域名 / IP / DNS / 网站」关系图或三句话分工。

核心原则：**入口在读者已有认知中（「域名就是网站地址」），收获在读者未曾想透的机制中（寻址名称 ≠ 内容托管；买了 ≠ 能访问）。**

### 1.5 当前文章不能越界解释的内容

依据 README、总计划、事实核查清单禁止写法与风险边界：

| 禁区 | 说明 |
|---|---|
| 规避备案教程 | 不写境外免备案操作路径（B08） |
| 域名 = 网站 | 不得暗示买了域名就有网站（B04） |
| 买了就能访问 | 不得写「注册域名即可上线/访问」（B01） |
| 后缀决定备案 | 不得写「.com 不用备案」（B02）；关键看服务器是否在中国大陆 |
| 账号实名 = 域名实名 | 两者独立（B03） |
| 备案 = 买域名 | 两件事，先后遇到（B05） |
| 写死促销价 / SEO 承诺 | 无官方实时价支撑时不写具体价格（B06）；不写后缀与排名强关联（B07） |
| DNS 配置教程 | 条目 01 scope 是「是什么」，不是「怎么配」（B10） |
| 备案 / 续费 / 后缀流程展开 | P1 事实可作边界提示，条目 01 不展开完整流程 |
| 灰色 / 暴富 / 培训号话术 | 系列通用禁区 |
| 未放行事实 | 不以 Wikipedia、建站营销文、聚名网等二手来源单独支撑 P0 |
| P2 待补项作核心支点 | ICANN 官方定义（G05）、精确价格对照（G01/G02）等不得作为条目 01 核心论证 |

**事实口径限定**（事实核查清单有条件通过）：

- P0 机制以 RFC 1034/1035 + 腾讯云《域名简介》为准；
- 264 号文引用须写「第一条第一款」，非第四条；
- 审核时长、宽限期、赎回期须带「通常」「约」「以后缀和注册商为准」。

## 四、结构命题层

### 4.1 核心问题

**条目 01**：域名到底是什么？它解决什么问题？个人开发者要记住什么？

### 4.2 当前文章审查问题

1. 候选命题能否压成一句可证明的机制句？格式是否符合系列标准：「读者通常以为 X → 实际上是 B → 它解决 Y → 个人开发者要记住 Z」？
2. 命题类型是否属于本条目允许的五种之一（概念澄清 / 选择判断 / 流程认知 / 避坑判断 / 国外对照）？条目 01 首选**概念澄清**（域名不是 A，而是 B）。
3. 命题是否只打一个点？能否在 6-8 张卡片内讲完，而不需要灰色操作或长文式铺垫才能成立？
4. 表面在讲「域名」；是否真正在解释「寻址名称与内容托管的分工」——而不是在讲「基础设施全貌」？
5. 候选命题若扩展到备案流程、后缀选购攻略、价格对比，是否应判为「命题过大」或「偏离条目 01 scope」？

### 4.3 不合格信号

1. 命题是「讲讲网站上线基础设施」——太大、太泛，无法对应单条图文；
2. 命题只有态度（「域名很重要」「别忽视域名」）没有机制（为什么不等于网站、分工是什么）；
3. 命题需要同时证明域名、服务器、备案三者的完整关系——应留给条目 06，不应在条目 01 展开；
4. 命题依赖未放行事实（促销价、SEO 排名、规避备案）才能显得「有用」；
5. 无法用一张卡片写出「个人开发者要记住」的可执行记忆点。

### 4.4 合格标准

条目 01 的结构命题合格，须同时满足：

- 能用系列标准格式完整填写：表面理解 / 真实说明 / 它解决什么 / 什么时候会遇到 / 个人开发者要记住 / 风险边界；
- 机制句单一、可复述，例如：「域名是 DNS 中的寻址名称，解决别人怎么找到你，不解决网页内容是什么」；
- 与主题包其他 9 条拟拆条目不重复，且为后续「服务器」「备案」「三者关系」留口径空间；
- 6 张卡片可完成概念建立 + 分工说明 + 行动提醒 + 风险边界，不需长文模块。

## 六、故事证据层

### 6.1 Claim / Grounds / Warrant 要求

| 项目 | 当前文章必须回答的问题 | 不合格表现 |
|---|---|---|
| Claim | 这条图文要证明的核心断言是什么？（如「域名是寻址名称，不等于网站本身」） | 只有科普语气，没有可证伪的核心句 |
| Grounds | 拿什么证明？P0 事实（E0101-E0106）中哪些钉子支撑 Claim？ | 用二手建站文、Wikipedia、促销页单独支撑；或引用待补 / 不采用事实 |
| Warrant | 为什么这些证据能证明 Claim？RFC 与官方文档如何支撑「名称空间标识 ≠ 内容托管」？ | 证据与结论跳跃（如从「要实名」直接推出「域名=网站」） |

**条目 01 可用 P0 证据锚点**（事实核查已放行）：

- E0101：域名是人类可读标识，DNS 映射为 IP；
- E0102：域名是 DNS 分层命名体系中的名称；
- E0103：域名标识寻址名称，不存储网页内容；网站在服务器上；
- E0104：IP / 域名 / DNS 三句话分工；
- E0105：访问链路四步；
- E0106：仅有域名、未部署与解析时，访问可能空白/报错；注册后还需实名、备案（如适用）、解析等。

**慎用 / 不采用**：E0105/E0106 的二手社区来源单独支撑；SEO 排名说法；写死价格；规避教程类表述（X01 不采用）。

### 6.2 当前文章机制链要求

```text
起点问题 → 旧办法解决了什么 → 旧办法解决不了什么 → 新办法如何出现 → 新办法带来什么结果 → 这个结果揭示什么规律
```

**条目 01 可改写为：**

```text
起点问题：域名到底是什么？
旧理解：域名 = 网站本身 / 买了就能访问
旧理解解决了什么：让人知道要买个网址
旧理解解决不了什么：为什么打不开、为什么要 DNS、内容和地址为何分离
机制说明：域名是 DNS 寻址名称 → DNS 译 IP → 连服务器 → 才有网页
结果：买了域名 ≠ 有了可访问的网站
规律：域名解决「找到你」，网站解决「看到你」；个人开发者先建立分工，再谈购买与配置
```

审查时检查：候选洞察是否能让这条链在 6 张卡内走通，且每一步有 P0 或 P1 事实支撑。

### 6.3 不合格信号

- Claim 过大（「搞懂域名就懂上线全流程」）；
- Grounds 依赖禁止写法（B01-B10）才能成立；
- Warrant 缺失：说了「域名像门牌号」但无法解释门牌号与房子的技术对应关系；
- 用故事/案例代替机制，但案例无法证明分工（如只讲「我朋友买了域名」）；
- 备案、续费、后缀细节抢占 P0 机制的证明篇幅。

### 6.4 合格标准

- 每个核心断言能对应至少一条已放行 P0 事实；
- 机制链可在卡片拆分表中一卡一点；
- 证据来源层级清晰：RFC/官方文档 > 云厂商官方说明；二手来源不单独支撑 P0；
- 「个人开发者要记住」可从机制链自然推出，而非作者态度。

## 七、承诺兑现层

本系列承诺兑现单位是**单条图文**（封面 + 前 3 张卡 + 全文 + caption），不是长文。

### 7.1 标题承诺审查

- 标题是否为具体问题句（如「域名到底是什么？」），而非「全网最全上线攻略」？
- 标题承诺的概念澄清，正文是否真的回答「是什么」而非跑题到「怎么买最便宜」？
- 若标题含「关系」「步骤」「为什么」，是否超出条目 01 scope？

### 7.2 开头承诺审查

- 封面 + 第 1 张卡是否抛出清楚问题？
- 第 2-3 张卡是否打破「域名=网站」或「买了就能开」的常见误解？
- 前 3 张卡是否让读者知道「值得翻完」——即能获得分工框架或排惑？

### 7.3 正文证明审查

- 中间卡片是否逐点证明结构命题，而非重复封面？
- 每张卡是否只讲一个点、30-90 字？
- 是否出现标题未承诺的过载内容（备案全流程、DNS 配置步骤、价格表）？

### 7.4 结尾兑现审查

- 最后 1-2 张卡是否给出「个人开发者要记住」的总结？
- caption 是否只做补充（场景、标签），不复制卡片全文、不写公众号长文？
- 读者翻完后能否复述收获，而非只记得「要去买域名」？

### 7.5 不合格信号

- 标题问「是什么」，正文写成购买教程或备案攻略；
- 封面承诺「一张图搞懂上线」，条目 01 只讲域名却暗示全流程已覆盖；
- 前 3 张卡没有打破误解，读者翻页动力不足；
- 卡片重复同一句话凑字数；
- caption 承诺收益、使用禁用表达。

### 7.6 合格标准

- 标题、封面、前 3 卡、正文、总结卡、caption 围绕同一结构承诺；
- 承诺范围与条目 01 scope 一致；
- 结尾兑现「是什么 + 解决什么 + 要记住什么」三环，不额外承诺未证明的内容。

## 八、当前文章一票否决项

1. **事实未放行**：P0 事实未通过核查，或使用事实核查清单标为「不采用」「待补资料且无保守写法」的内容作为核心支点。
2. **目标客户明显不匹配**：命题面向运维工程师查 DNS 配置，或面向想规避备案的读者——与系列读者画像和禁区冲突。
3. **命题无法证明**：核心断言无法对应已放行 P0/P1 事实，或依赖二手营销文、SEO 谣言、促销价才能成立。
4. **命题过大**：条目 01 试图承担「基础设施全貌」「上线全流程」「后缀选购大全」——应拆到其他条目。
5. **只有态度没有机制**：全文只有「域名很重要」「别忽视」，没有 IP/DNS/服务器/内容分工。
6. **承诺错位**：标题/封面说「是什么」，正文主写「怎么避备案」「怎么最低价购买」；或制造收益承诺、焦虑话术。
7. **单条图文超载**：一条图文同时讲域名、服务器、备案三个不相关概念；或单卡超 100 字未拆分。
8. **灰色与规避**：出现绕备案、绕支付、境外免备案操作、税务优化、海外收款规避等审稿政策一票否决项。
9. **禁止写法踩线**：B01-B10 任一核心支点（如「买了就能访问」「域名=网站」「.com 不用备案」）。
10. **口吻越界**：培训号腔、暴富腔、论文腔、AI 腔（见文风禁用清单）。

## 九、评分方式

| 维度 | 评分问题 | 分值 |
|---|---|---|
| 目标客户匹配 | 是否匹配个人开发者兴趣入口、前置知识、认知收获期待和可迁移场景 | 1-5 |
| 命题清晰度 | 是否能压成一句单一、可证明的机制句，并填满系列标准格式 | 1-5 |
| 解释深度 | 是否解释因果、分工、访问链路、代价和边界（非只给定义） | 1-5 |
| 认知收获 | 是否让读者获得新概念、新框架或新理解（门牌号、三句话分工等） | 1-5 |
| 证据承载 | P0 事实是否能支撑 Claim；二手来源是否未越权 | 1-5 |
| 迁移价值 | 读者能否用同一框架理解「买了为什么打不开」等相邻场景 | 1-5 |
| 承诺兑现 | 标题、前 3 卡、正文、总结、caption 是否围绕同一结构承诺 | 1-5 |

**建议阈值：**

- **32 分以上**：可作为条目 01 全文结构命题；
- **28-31 分**：可作为主线候选，但需修补机制链或删减超载内容；
- **23-27 分**：适合作为辅助命题或某一两张卡片的子命题；
- **23 分以下**：不建议作为条目 01 主命题。

**特别规则**：若目标客户匹配低于 3 分，即使命题本身有知识深度，后续分析卡也必须谨慎推荐，必要时建议放弃。

**主题包层补充**：完整主题包拟拆 10 条结构命题；各条目须独立评分，不得因「主题包重要」而降低单条门槛。

## 十一、最终提醒

1. **入口在读者已有认知中，收获在读者未曾想透的机制中**——条目 01 从「域名就是网址」切入，收到「寻址名称 ≠ 网站内容」。
2. 本文件是审查标准，不是分析结论；不得在本卡中暗示「哪个候选洞察最好」。
3. 结构命题单位是**单条图文**，试水 scope 仅条目 01；不要用主题包全貌标准去稀释单条门槛。
4. 凡涉及备案、实名、续费、后缀，只用已放行 P1 事实作**边界提示**，不写流程教程，不写死数字。
5. 承诺兑现审查前移到洞察阶段：候选命题先问「标题像什么问题、6 张卡够不够证、会不会跑题成购买/避坑教程」。
6. 事实核查结论为「有条件通过」——分析卡引用事实时须遵守第八节一票否决与 1.5 节口径限定。
