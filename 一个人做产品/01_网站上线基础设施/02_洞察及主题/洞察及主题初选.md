## 二、可用事实边界

### 2.1 可作为核心支点的事实

| 编号 | 事实 | 使用限制 |
|---|---|---|
| E0101 | 域名是为便于记忆 IP 而设的人类可读标识；DNS 负责将域名映射为 IP | P0；机制表述以 RFC 1034 + 腾讯云《域名简介》为准 |
| E0102 | 域名是 DNS 分层命名体系中的名称，非随意字符串 | P0；正文可简化为「从右往左分层」一句 |
| E0103 | 域名标识寻址名称，本身不存储网页内容；网站在服务器上 | P0；条目 01 核心纠偏钉子 |
| E0104 | IP 给机器看，域名给人记，DNS 负责翻译 | P0；三句话分工，缺一不可 |
| E0105 | 访问链路：输入域名 → DNS 得 IP → 连服务器 → 返回网页 | P0；不写「输入域名即打开网页」 |
| E0106 | 仅有域名、未部署内容与解析时，访问可能空白/默认页/报错 | P0；备案在国内服务器场景仅作边界提示 |
| D01 | 域名双重属性：技术向寻址名称 + 产品向付费名字资产 | 口径已调和，可并存表述 |
| E01P1-13 | 云平台账号实名 ≠ 域名实名 | P1；可作国内语境纠偏，不抢 P0 主线 |
| E01P1-08 | 是否备案关键看服务器是否在中国大陆，与后缀无必然对应 | P1；条目 01 最多一句边界，不展开备案流程 |

### 2.2 不得作为核心支点的事实

| 编号 | 事实 | 原因 |
|---|---|---|
| X01 | 境外免备案操作教程 | 不采用；系列风险边界 |
| X02 | 具体促销价「首年 0 元」等 | 限制使用；G01 待补官方价 |
| X03 | SEO/排名与后缀强关联 | 不采用；无权威来源 |
| X04 | 抢注要价、恶意案例故事 | 不采用；易制造焦虑 |
| X05 | DNS 配置步骤详解 | 条目 01 scope 是「是什么」，非「怎么配」 |
| E01P2-01 | ICANN 协调全球域名体系 | 待补资料；条目 01 可不展开 |
| G01 | 域名注册/续费/赎回标准价 | 待补；条目 01 可不写价格 |
| E01P1-04 / E01P1-06 等 | 审核时长、宽限期、赎回期精确天数 | 口径待定；须带「通常」「约」「以后缀和注册商为准」 |

## 三、外部内容约束

> 注：外部内容搜索.md 未产出。以下约束来自资料.md 对二手建站科普、注册商营销文、培训号常见写法的归纳；待 ecosystem-scan 后复核。

### 3.1 必须避开的常见写法

1. **「买了域名就能上线」**——忽略 DNS 解析、服务器部署、内容存在；与 B01 红线直接冲突。
2. **门牌号类比单飞**——只讲「域名=门牌号」却不补「房子里有什么在服务器上、还要 DNS 指路」，读者仍会误以为域名即网站。
3. **保姆级注册/解析全流程**——条目 01 是 6 卡概念科普，不是「十分钟搞定域名」教程；系列禁用培训号腔。
4. **后缀决定论**——「.com 不用备案」「.cn 百度加权」等营销口径；事实核查已明确备案看服务器位置。
5. **价格促销噱头**——「首年 0 元」「1 元购域名」等活动价时效强，易误导且 G01 未核。

### 3.2 可以借鉴但必须改造的传播机制

1. **三句话分工（IP / 域名 / DNS）**— 常见且有效，但须落到 E0104/E0105 机制链，不写配置步骤。
2. **「域名≠网站」纠偏**— 高频刚需，但须用 E0103/E0106 钉子支撑，避免只喊口号不解释机制。
3. **国内实名卡点**— 读者真实痛点，但条目 01 最多点到「名字资产在国内还要过实名」，不展开审核天数细节。
4. **后缀选择清单**— 可一句带过 `.com`/`.cn`，不写 SEO 承诺、不写可备案后缀全表。

## 四、候选洞察

### 主题包价值（跨条目，为条目 01 定调）

---

### 候选 1：寻址名，不是网站本体（推荐·条目 01 主洞察）

| 项目 | 内容 |
|---|---|
| 核心判断 | 域名解决的是「别人怎么找到你」，不解决「网页内容是什么」；它是 DNS 体系里的分层寻址名称，不是网站本身。 |
| 回答的读者问题 | 我买了域名，为什么还打不开网站？域名到底算不算是「我的网站」？ |
| 关键事实支撑 | E0103（寻址名称≠内容托管）；E0104（IP/域名/DNS 分工）；E0105（访问链路）；E0106（仅有域名不能访问） |
| 与外部常见写法的差异 | 不只喊「域名像门牌号」，而是钉住机制链：名字 → DNS 翻译 → IP → 服务器上的内容；纠正「域名=网站」「买了就能访问」两层误解 |
| 传播优势 | 反常识力度适中、事实稳固；个人开发者最高频卡点；6 卡图文可一张一钉 |
| 结构风险 | 门牌号类比若用过头，读者仍可能忽略 DNS；须配一句「还要翻译和连服务器」 |
| 事实风险 | 低；P0 全部放行 |
| 适合进入传播学分析 | 是 |

说明：

这是条目 01 最稳的主轴。读者带着「域名=网站」的默认假设进来，文章要做的不是堆术语，而是用 E0103–E0106 把「名字—翻译—机器—内容」四层关系讲清。反常识点在于：域名是上线链条里最早遇到、却最常被误当成终点的环节——你买的是「被人找到的名字」，不是「房子里的装修」。

---

### 候选 2：双重身份——技术寻址名 + 国内名字资产（推荐·条目 01 辅洞察）

| 项目 | 内容 |
|---|---|
| 核心判断 | 域名有两张脸：在 DNS 里它是分层寻址名称；在个人开发者实践里，它是要花年费、过实名审核才能持续使用的「名字资产」。 |
| 回答的读者问题 | 域名到底是技术概念还是「买个东西」？为什么国内买域名还要等审核？ |
| 关键事实支撑 | D01（双重属性口径已调和）；E0101/E0102（技术定义）；E01P1-02/E01P1-03（实名核验硬门槛）；E01P1-13（账号实名≠域名实名） |
| 与外部常见写法的差异 | 不写「建站第一步保姆级注册」，而是点明：国内语境下，域名不只是 RFC 里的命名标识，还是受监管的名字使用权；但条目 01 不展开注册教程 |
| 传播优势 | 贴合中国个人开发者真实场景；解释「为什么买域名还要等」的困惑 |
| 结构风险 | 若实名/审核写太多，条目 01 会从「是什么」滑向「怎么买」；须严格边界 |
| 事实风险 | 中；审核时长 E01P1-04 为「按口径通过」，正文须带「通常」「约」 |
| 适合进入传播学分析 | 是 |

说明：

D01 口径冲突已在事实核查中调和：技术向与产品向不矛盾。对国内读者，这一洞察补充了「反直觉的第二层」——域名不是写完代码就自动有的东西，也不是买了就永久生效的抽象符号，而是有有效期、有实名约束的资产。条目 01 可用 1–2 张卡片轻点，把「名字资产」与国内实名门槛挂上钩，为主题包后续备案条目埋伏笔。

### 候选 3：国内卡点不在技术，在概念混淆（备选）

| 项目 | 内容 |
|---|---|
| 核心判断 | 个人开发者真正卡住的，常常是「域名=网站」「账号实名=域名实名」「备案=买域名」等概念没分清，而不是 DNS 技术本身有多难。 |

说明：

洞察成立，但更适合作为候选 1 的「收束句」或主题包整体叙事，而非条目 01 独立主轴。条目 01 篇幅仅 500–800 字、6 卡，辟谣项过多会挤占机制解释空间。

## 六、初步推荐

### 推荐进入后续分析的候选

```text
候选 1：寻址名，不是网站本体
候选 2：双重身份——技术寻址名 + 国内名字资产
```

推荐理由：

1. **候选 1** 锚定全部 P0 事实钉子（E0101–E0106），是条目 01「域名到底是什么」的唯一必答；机制链清晰，适合 6 卡逐层推进。
2. **候选 2** 提供国内语境差异化，把 D01 双重属性转化为读者可感知的「名字资产」认知，但不越界到注册教程。
3. 两者组合：先破「域名=网站」，再立「域名是什么 + 在国内它还多一层实名约束」——符合总计划暂定逻辑链，且与主题包后续条目自然衔接。

### 备选候选

```text
候选 3：国内卡点不在技术，在概念混淆
```

备选原因：

洞察成立，但作为条目 01 主洞察会稀释机制深度；建议将 E01P1-13（账号实名≠域名实名）等误解纠正嵌入候选 2 的 1 张卡片，而非单独成篇。

### 不建议候选

| 候选 | 不建议原因 |
|---|---|
| 以备案/后缀/续费为主轴的洞察 | 超出条目 01 scope；事实核查要求仅边界提示 |

## 七、对后续传播学分析的要求

后续传播学分析必须重点检查：

1. **反常识力度是否适度**——「域名≠网站」有认知差，但不宜包装成「震惊体」；克制科普气质优先。
2. **门牌号类比是否会误导**——若采用，须同步出现 DNS/服务器/content 机制钉，避免只剩比喻没有机制。
3. **国内实名是否喧宾夺主**——候选 2 的「名字资产」表述不能超过候选 1 的机制主线；实名最多占 1 卡篇幅。
4. **与主题包后续条目的入口衔接**——条目 01 结尾是否自然引出「那 DNS/服务器/备案又是什么关系」，而不写成孤立概念卡。
5. **待 ecosystem-scan 后复核**——外部内容搜索产出后，须对照第三节约束是否需增补「写烂角度」清单。

## 八、对后续大纲的初步约束

这里只给约束，不写大纲。

1. **6 卡结构建议沿机制链推进**：误解破冰 → 技术定义（寻址名）→ IP/域名/DNS 分工 → 访问链路 → 域名≠网站（E0106）→ 国内语境轻点（名字资产+实名边界）→ 收束到主题包地图。
2. **每张卡 30–90 字**；总字数 500–800；不写长文式引言、结尾、小尾巴。
3. **P0 机制表述以 RFC 1034 + 腾讯云《域名简介》为准**；门牌号类比后必须补「内容在服务器、还要 DNS 翻译」。
4. **备案、续费、后缀、DNS 配置均不展开**；E01P1-08 最多一句「关键看服务器在哪里」。
5. **禁止写法 B01–B10 全部遵守**；尤其 B04「域名=网站」、B01「买了就能访问」须在卡 1 或卡 2 正面破除。
