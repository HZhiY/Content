## 二、读者审读定位

### 2.1 本文目标读者

| 目标读者 | 可能关心的问题 | 前置知识 | 阅读场景 | 转述场景 |
|---|---|---|---|---|
| 会写代码、准备做第一款小产品的中国个人开发者 | 域名要买吗？域名和网站是不是一回事？代码写完了下一步是什么？ | 会写 HTML/小程序；听过域名、服务器、备案 | 小红书搜索「域名是什么」；周末准备上线前收藏 | 群聊有人问「域名买了怎么还不能访问」时转发 |
| 用 AI 写代码、项目快完成但从未上线的人 | demo 怎么让别人访问？域名是否可选？ | 会用 Cursor 等工具；知道要「部署」但模糊 | 信息流刷到处境钩「买了域名为什么还打不开」 | 转给同样用 AI 做 side project 的朋友 |
| 听过域名但混淆门牌号/网站/服务器的初学者 | 域名算不算「我的网站」？买域名算上线了吗？ | 日常上网；可能刚注册域名看到空白页 | 收藏以备买域名前查阅；第一次注册后困惑时回看 | 向非技术朋友解释「域名是名字不是网站」 |
| 不想被割韭菜、反感副业暴富话术的信息型读者 | 域名这块有没有坑？正规路径是什么？ | 对「十分钟搞定」「零成本」有警惕 | 主动筛选克制科普笔记收藏 | 转给同样做产品、反感培训号腔的朋友 |

**次要可接住读者（须控制术语密度）**：纯产品/运营背景、依赖他人开发的非技术读者——可概念级理解，但 DNS/IP 首次出现必须人话翻译。

**自然过滤、非本文服务对象**：运维查 DNS 配置者、域名炒卖/SEO 运营者、企业 IT 采购者——期待保姆级教程或 SEO 攻略者会在 scope 内自然失望，不算读者侧失败。

### 2.2 读者审读只回答的问题

1. 目标读者为什么会点开这条图文，第一屏能否立刻感到「这和我上线有关」？
2. 6 张卡片翻下来，读者能否跟上「误解 → 寻址名定义 → 分工 → 链路 → 买了≠能访问 → 国内轻点」？
3. 读完后能否用一句话复述「域名是什么、不是什么、个人开发者为什么要关心」？
4. 读者是否愿意收藏或转给具体对象，对方能否接得住？
5. 标题/封面/前 3 卡/末卡/caption 是否兑现同一个读者承诺？

### 2.3 读者审读不回答的问题

1. 不做事实裁决（P0 是否成立、264 号文引用位置等交主编/事实核查）。
2. 不决定最终发布标题（标题方案在 07 阶段定稿）。
3. 不重写卡片正文、不改 6 卡结构、不新增未经核查的事实。
4. 不调整大纲条目拆分或主题包 scope。
5. 不替主编判断是否最终发布。
6. 不因为「更刺激」建议突破 B01–B10、系列禁区或规避教程边界。

## 三、本文读者侧主承诺

### 3.1 读者看到标题或开头时，以为本文会回答什么

```text
域名到底是什么？它和网站、服务器是不是一回事？
我买了域名，为什么还打不开？
买域名算不算「有了网站」？
```

### 3.2 正文必须让读者获得什么

```text
域名是 DNS 分层命名体系中的寻址名称——它解决「别人怎么找到你」，不解决「网页内容是什么」。
IP / 域名 / DNS 三句话分工 + 一条极简访问链路（域名→DNS→IP→服务器→网页）。
买了域名 ≠ 有了可访问的网站；注册只是第一步。
在国内，域名还是「名字资产」（年费、实名），账号实名 ≠ 域名实名（轻点即可）。
至少一张可截图收藏的分工图或「是什么/不是什么」对照。
```

### 3.3 不能向读者承诺什么

1. 不能承诺「看完就懂上线全流程 / 备案 / DNS 配置 / 后缀选购」——本篇只闭环「域名是什么」。
2. 不能承诺「买了域名就能访问 / .com 不用备案 / 账号实名了域名就不用实名」——触犯 B01/B02/B03。
3. 不能承诺「保姆级注册教程 / 十分钟搞定 / 免备案攻略 / 具体促销价或写死审核天数」——培训号腔 + 事实边界。
4. 不能把主题包价值升格为封面主轴——「代码写完后还要过 DNS/服务器/备案全套关卡」6 卡装不下，标题承诺无法兑现。
5. 不能把候选 3「概念混淆避坑清单」作主承诺——易变「十大坑」，读完知道「我搞混了」但说不出域名机制。

## 四、读者审查维度

### 4.1 点击与第一屏

| 审查项 | 合格标准 | 不合格信号 |
|---|---|---|
| 点击理由 | 主动搜索「域名是什么 / 域名要买吗」或被动被「买了域名为什么还打不开」处境钩接住；问题具体、可搜索、无夸张承诺 | 封面像「上线全套攻略」「保姆级建站」「免备案」；只有系列定调无单点问题 |
| 第一屏问题感 | 卡 1 15–30 字内抛出清楚问句或处境；读者立刻知道「这条在讲域名，不是泛泛上线」 | 卡 1 堆 5 个名词；先抛 RFC 术语树；封面写培训口号 |
| 标题/开头承接 | 问句/处境钩与正文 6 卡机制链一致；前 3 卡须打破「域名=网站 / 买了就能访问」 | 封面问「是什么」，正文主要写「怎么买/怎么实名」；前 3 卡仍不回答「域名是什么」 |

### 4.2 理解门槛

| 审查项 | 合格标准 | 不合格信号 |
|---|---|---|
| 前置知识 | 默认读者会写代码或用过 AI 写代码、听过域名；不要求已懂 DNS 配置 | 假设读者已懂 A/CNAME 记录、ServerHold、ICANN 体系 |
| 人名/机构/制度解释 | DNS→「把域名翻译成 IP 的系统」；IP→「给机器看的数字地址」；解析→「让域名指向哪台服务器」；备案/实名仅边界一句 | DNS/IP/解析首次出现无翻译；264 号文误写「第四条」；账号实名与域名实名不区分 |
| 概念释放时机 | 卡 1–2 处境+破误解；卡 3 起逐步托机制；门牌号后同卡或下一卡必有 DNS + 服务器钉 | 门牌号单飞无机制；卡 1 即抛完整判断无翻页动力；分层命名在门牌号桥接前出现 |

### 4.3 阅读节奏

| 审查项 | 合格标准 | 不合格信号 |
|---|---|---|
| 段落长度 | 每张卡 30–90 字、≤8 行；1–3 行为主；单句成段允许 | 单卡超 100 字未拆分；单卡混讲实名+备案+后缀 |
| 信息密度 | 一卡一点；6 卡沿机制链推进；总 500–800 字 + caption 100–200 字 | 一条图文同时讲 DNS 配置、备案流程、后缀选购；caption 复制 6 卡全文 |
| 中段推进 | 卡 3–4 分工/链路卡建立翻页理由；每 2 卡内至少一次回到「我做第一款产品为什么要关心」 | 卡 3–5 像资料堆叠或辟谣清单；中段与「域名是什么」关系不清 |
| 转折自然度 | 「很多人以为…→ 其实是寻址名 → 还要 DNS 翻译和内容在服务器」逐步浮出 | 连续 2 卡只有判断无分工；反常识口号无机制（「原来一直搞错了！」） |

### 4.4 信任感

| 审查项 | 合格标准 | 不合格信号 | 交接方式 |
|---|---|---|---|
| 判断是否从事实浮出 | 「域名≠网站」「买了≠能访问」后有 E0103/E0106 机制钉；分工卡可对应三句话 | 只剩门牌号比喻；反常识口号无 DNS/IP/服务器链 | 交主编/事实核查 |
| 是否过度归因 | 不把「打不开」归因为单一原因（如「只看 DNS」）；不写 SEO/后缀决定排名 | 「选错后缀就完了」「.cn 百度加权」；写死「1 天搞定」「30 天宽限期」作普适事实 | 交主编/事实核查 |
| 是否让读者觉得跳 | 机制链每步可复述；国内实名/备案仅边界轻点 | 实名/审核突然展开成注册教程；备案流程占 2 卡以上 | 交主编 |
| 培训号/暴富感 | 像开发者递笔记；克制恍然大悟 | 保姆级、十分钟搞定、震惊体、收益暗示 | 读者侧必改 |

### 4.5 获得感

| 审查项 | 合格标准 | 不合格信号 |
|---|---|---|
| 一句话收获 | 读完能说出：「域名是寻址名，解决找到你，不解决内容是什么；买了域名不等于有了网站」 | 只能记住「好像挺有用」但说不出具体点 |
| 新解释 / 新框架 | 至少带走三句话分工 + 访问链路四步，或「是什么/不是什么」对照卡 | 只知道「域名≠网站」口号，说不清 DNS 在哪一环 |
| 结尾余味 | 末卡收束可复述判断 + 可选一句「域名只是上线地图第一块」；不贩卖「还有很多要学」焦虑 | 突然拔高到备案/服务器机制详解；结尾变避坑清单或培训 CTA |

### 4.6 转述价值

| 审查项 | 合格标准 | 不合格信号 |
|---|---|---|
| 转给谁 | 一起做产品的开发者朋友、用 AI 写代码准备上线的人、刚买域名困惑的同学 | 只能转给「也看小红书的人」但说不清为什么 |
| 为什么转 | 省解释成本——「域名是名字不是网站」「买了还要解析和部署」 | 转发只为「收藏了再说」无对话价值 |
| 对方是否接得住 | 对方有过或即将有「买了打不开 / 域名要买吗」困惑；截图分工卡对方能看懂 | 转述需附带长篇背景；非目标读者接不住术语 |
| 转发后对话价值 | 自然引向「那 DNS 呢？」「服务器放哪？」——系列后续条目，本篇不终结也不抢 scope | 转发后对方问「怎么配解析」本篇完全答不上且未设边界 |

## 五、读者侧必改项定义

后续读者审读中，如出现以下问题，应列为必改项：

1. **目标读者不知道为什么要读**：封面/卡 1 无清楚问句或处境，或像「上线全套攻略」导致 scope 错位。
2. **第一屏无法理解要解决什么问题**：前 3 卡未打破「域名=网站 /  bought就能访问」，或仍不触及「域名是什么」。
3. **关键概念不解释导致无法继续读**：DNS/IP/解析首次出现无人话翻译；非技术读者在卡 3–4 明显掉线。
4. **某一卡信息密度过高**：单卡超 100 字、超 8 行，或一卡混讲实名+备案+后缀+DNS 配置。
5. **判断跳得太快读者不信**：门牌号单飞无 DNS + 服务器钉；「域名≠网站」无机制链支撑。
6. **中段与主问题关系不清**：卡 3–5 变辟谣清单或注册教程，读者不知道还在回答「域名是什么」。
7. **承诺不兑现**：标题/封面问「是什么」，正文主写「怎么买/怎么实名」；或暗示全流程却只讲一块。
8. **结尾突然拔高或另起话题**：末卡展开备案流程、DNS 配置，或「十大坑」焦虑收束。
9. **读完无法复述核心收获**：说不出寻址名分工或「买了≠能访问」。
10. **读者可能严重误解**：以为「买了域名就能上线」「.com 不用备案」「账号实名=域名实名」——且非事实核查能自动解决的表达问题。
11. **触犯系列/文风禁区（读者侧可见）**：培训号腔、暴富腔、震惊体、灰色规避暗示——直接导致目标读者信任崩塌。
12. **形态不合格**：单条图文 500–800 字外、单卡 30–90 字外、强行长文式引言/结尾/小尾巴——手机阅读体验阻断。

### 5.1 必改项和建议项区别

| 类型 | 定义 | 后续处理 |
|---|---|---|
| 必改项 | 不改会导致目标读者读不下去、看不懂、不信、无收获，或严重误解 | 修订前必须处理 |
| 建议项 | 改了更顺、更有收藏感或转述力，但不构成读者侧阻断（如某卡可再短 10 字、caption 场景可更具体） | 可由主编决定是否采纳 |
| 可保留项 | 对读者体验有效，应尽量保留（如三句话分工收藏卡、处境钩、国内名字资产轻点、末句系列钩子） | 修订时避免误删 |

### 6.1 结论类型

| 分数 / 条件 | 读者侧结论 | 后续处理 |
|---|---|---|
| 31 分以上，且无关键低分项 | 读者侧通过 | 可进入主编审稿 |
| 26–30 分，必改项可局部处理 | 小修后通过 | 处理必改项后进入主编审稿 |
| 21–25 分，存在明显体验断裂 | 大修后复审 | 修改后重新读者审读 |

**条目 01 专项低分预警**：若读者反映「像门牌号同质帖」「像注册教程预告」「像上线全景却只讲域名」，即使总分不低，也须至少列为建议项并检查是否触及必改项 6、7、8。

## 八、读者审读红线

后续读者审读员不得：

1. 不得做事实裁决（如判定 E0106 口径是否正确、264 号文引用对错）。
2. 不得新增事实、促销价、写死审核天数。
3. 不得重写卡片正文或 caption 全文。
4. 不得改写文章方向主承诺（不得建议改回「上线全景」或「怎么买域名」作主承诺）。
5. 不得建议使用方向把控已放弃的主洞察（主题包价值、候选 3 清单、备案/后缀/DNS 配置主轴）。
6. 不得为吸引点击建议使用震惊体、保姆级、免备案、暴富话术。
7. 不得把主编侧结构问题（6 卡分工是否符合大纲）伪装成纯读者感受而不说明卡位。
8. 不得只写「好读/不好读」——必须标明卡号、caption 或封面，并说明对哪类目标读者的影响。
9. 不得要求条目 01 展开 DNS 配置教程以满足「查操作步骤读者」——应标记 scope 边界，建议 caption 轻点后续条目。
10. 不得用其他系列或历史文章作对比标准。

## 九、给主编的交接说明

主编审稿条目 01 时应重点查看读者审读中的：

1. **读者侧必改项**——尤其第一屏、前 3 卡、承诺兑现、复述测试失败项。
2. **信任感低分项**——门牌号单飞、B01/B04 类误解未破除、培训号感。
3. **标题/封面/卡 1–3/末卡/caption 承诺一致性**——问「是什么」是否写成「怎么买」。
4. **复述测试与收藏卡**——是否带走分工框架；可截图卡是否存在且清晰。
5. **读者侧标记「需主编判断」项**——事实口径、同质化、候选 2 是否越界为教程、非技术读者术语密度。
6. **与放弃项冲突**——主题包价值升格、候选 3 清单化、备案/后缀/DNS 配置抢篇幅。

主编可采纳、升级或驳回读者意见，但必须说明理由。

## 十、方向把控 → 读者侧检查清单（条目 01 专用）
