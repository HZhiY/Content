# 审稿政策配置

> 适用系列：用量化思维理解世界  
> 用途：供大纲审阅、读者审读、主编审稿、修订、发布检查等 agent 统一审稿红线、退回条件和质量闸门。  
> 核心原则：宁可退回上游，也不能让事实不稳、承诺不兑现、结构不闭环的稿件进入发布。

---

## 一、审稿总原则

本系列所有稿件必须同时满足：

1. 事实安全；
2. 方向明确；
3. 主承诺能被正文兑现；
4. 结构链条闭合；
5. 读者能复述核心机制；
6. 文风符合系列基调；
7. 不越过投资合规边界；
8. 不用情绪、金句或标题掩盖论证不足。

一句话原则：

```text
审稿不是把文章写得更猛，而是确认它是否真的成立。
```

---

## 二、质量闸门

### 2.1 事实闸门

以下情况不得进入大纲、草稿、标题或发布阶段：

- P0 事实存在待核；
- 核心事实来源不足；
- 关键数据、年份、研究结论存在冲突；
- 事实核查清单标注"不采用"的材料仍被使用；
- 待补资料被当作正文支点；
- 相关关系被写成因果关系；
- 多因素解释被写成唯一原因；
- 行为金融研究结论被夸大（例如"亏损痛苦是收益快乐的两倍"需要查证准确口径）。

### 2.2 方向闸门

以下情况必须退回方向把控或上游分析：

- 文章不知道自己主要服务五层递进中的哪一层；
- 主承诺过大，正文无法兑现；
- 方向把控中的放弃项被重新引入；
- 文章同时试图解释多个大问题；
- 结尾升维与正文主线不一致；
- 行为金融篇变成了策略教学；
- 人生迁移篇变成了鸡汤。

### 2.3 大纲闸门

以下情况不得进入草稿：

- 大纲没有清楚的承诺链；
- 每一节与主承诺关系不明；
- 只是资料顺序，不是论证顺序；
- 事实支点不足；
- 引言、正文、结尾不服务同一问题；
- 大纲审阅存在必改项但未处理。

### 2.4 审稿闸门

审稿采用**四读制**（A 阶段和 B 阶段各自独立执行），每轮顺序不得打乱：

```text
A1. free-review     → 自由审读（零上下文盲审，只读正文本身）
A2. reader-review   → 读者审读（目标读者视角）
A3. density-edit    → 内容密度审读（字数、段落、信息密度、强调分布）
A4. editor-review   → 主编审稿（事实安全、方向成立、结构闭环、是否可发布）
```

A1–A3 三读全部落盘后才可以执行 A4。

#### 各角色分工

| 审稿角色 | 主要判断 | 产物 |
|---|---|---|
| 自由审读 | 不带任何上游信息，零上下文读正文——能否看懂、是否想继续、哪里卡住 | `自由审读_草稿.md` / `自由审读_修订稿 阶段B vN.md` |
| 读者审读 | 目标读者是否想读、能否看懂、是否掉线、能否复述 | `读者审读 vN.md` / `读者审读 阶段B vN.md` |
| 内容密度 | 字数是否合适、段落是否过长、信息密度是否过高、强调是否均匀 | `内容密度审读 vN.md` / `内容密度审读 阶段B vN.md` |
| 主编审稿 | 事实是否安全、方向是否成立、结构是否闭环、是否可发布 | `主编修改建议 vN.md` / `主编修改建议 阶段B vN.md` |

#### 阶段 A 审稿循环（审 `04_草稿/草稿.md`）

- 轮次：v1..v5
- 每轮顺序：A1 free-review → A2 reader-review → A3 density-edit → A4 editor-review
- 主编结论：
  - 「进入下一轮修订」→ 对草稿做修订或产出修订稿 v1；重跑 A1–A4
  - 「大修后复审」→ 改稿后重跑 A1–A4
  - 「退回上游」→ 停止，退回 3.x / 2.x / 1.x
  - 「内容冻结，可进 release-check」→ 结束阶段 A，进入阶段 B
- 上限：第 5 轮仍有必改 → 写 `06_修订与发布/人工介入报告.md`，停止

#### 阶段 B 审稿循环（审 `06_修订与发布/修订稿 vN.md`）

- 轮次：v1..v5
- 每轮顺序：B1 free-review → B2 reader-review → B3 density-edit → B4 editor-review
- 主编结论：
  - 「进入下一轮修订」→ draft-revise 产出修订稿 vN+1.md，重跑 B1–B4
  - 「大修后复审」→ 改稿后重跑 B1–B4
  - 「退回上游」→ 停止
  - 「内容冻结，可进 release-check」→ 结束阶段 B，进入 6.1
- 上限：第 5 轮仍有必改 → `人工介入报告.md`，停止

#### 改稿优先级（draft-revise 内）

```text
H1 成稿卫生 → 主编/读者必改 → 本版必处理建议项 T*
```

每轮修订后必须检查：

- 自由审读侧是否发现新卡点；
- 读者侧必改项是否处理；
- 密度审读侧是否发现字数/段落/信息密度问题；
- 主编必改项是否处理；
- 未采纳意见是否有理由；
- 修订是否引入新风险。

#### 字数统计口径

- **统计对象**：`修订稿 vN.md` 纯正文（引言至结尾）
- **计入**：汉字 + 标点符号
- **不计入**：文件头 metadata、章节号、`修订执行说明 vN.md` 全文
- 修订执行说明中必须写明「正文含标点字数」

#### 成稿卫生 H1（density-edit 与 editor-review 共同检查）

以下为成稿卫生硬伤，命中任意一条即为必改：

1. 内部编号（K/F/E 等）残留在正文
2. 编辑指令句（「事实红线」「必须分写」「不可混用」）残留在正文
3. 写作执行说明自检表残留在读者可见正文
4. 作者提示腔（「读者应该注意到」「本文要说明的是」等）
5. 段落超过 150 字（手机阅读硬限）
6. 英文块超过一行或超过 2 处
7. 概念连续出现超过 3 个未配现实翻译

### 2.5 成稿终审闸门

发布检查通过后、HTML 生成前，必须执行格式终审：

- **subagent**：`06-format-final-check`
- **产物**：`06_修订与发布/成稿终审.md`
- **检查项**：编辑标记残留、metadata 污染、字数、加粗使用、HTML 就绪度
- **闸门**：结论 = `通过，可进 html-build`；否则退回改格式/卫生，不得进 HTML 阶段

### 2.6 发布闸门

发布检查未通过，不进入标题、插图和 HTML 阶段。

发布检查必须判断：

- 是否允许进入标题阶段；
- 标题可以承诺什么；
- 标题不能承诺什么；
- 是否允许进入插图和 HTML 阶段。

## 三、审稿红线

### 3.1 事实红线

禁止：

1. 编造研究结论；
2. 使用未经核查的行为金融数据；
3. 改写事实核查清单限定口径；
4. 把"可能""部分""倾向"写成确定结论；
5. 用单一案例证明普遍规律；
6. 用学术研究结论直接暗示投资建议；
7. 把相关关系写成因果关系。

### 3.2 投资合规红线

禁止：

1. 推荐具体股票、基金、币种、平台；
2. 承诺收益或暗示稳赚；
3. 以历史收益诱导现实决策；
4. 使用"稳赚""保本""必胜"等表达；
5. 暗示"照做就能赚钱"；
6. 把回测说成未来保证。

### 3.3 结构红线

禁止：

1. 开头承诺一个问题，正文讲另一个问题；
2. 资料堆砌但没有机制链；
3. 故事推进压过机制解释；
4. 每节都精彩但整体不闭合；
5. 结尾拔高到正文没有证明的位置；
6. 行为金融篇变成策略教学；
7. 人生迁移篇变成鸡汤。

### 3.4 文风红线

禁止：

1. 投资承诺口吻；
2. 荐股荐基荐币；
3. 嘲笑普通投资者；
4. 贩卖焦虑；
5. 过度鸡汤；
6. 数学炫技；
7. 神秘化量化；
8. 过度绝对化；
9. 过度升维。

### 3.5 标题红线

禁止标题：

1. 承诺正文没有证明的内容；
2. 放大事实核查清单限定口径；
3. 使用平台风险词；
4. 只靠悬念不说明主题；
5. 用抽象词替代具体入口。

---

## 四、退回规则

| 问题类型 | 退回阶段 |
|---|---|
| 缺事实、事实冲突、来源不足 | 事实补充 / 事实核查 |
| 主承诺过大、方向不清 | 方向把控 |
| 洞察组合不成立 | 洞察初选 / 传播分析 / 结构分析 |
| 大纲承诺链断裂 | 大纲规划 |
| 读者看不懂或明显掉线 | 读者标准 / 大纲 / 修订 |
| 主编必改项较多 | 修订 |
| 三轮仍不通过 | 三轮失败报告 |
| 发布检查不通过 | 修订或指定上游阶段 |
| 投资合规问题 | 立即停止，退回草稿 |

---

## 五、三轮失败机制

审稿修订最多三轮。

如果第 3 轮后仍有主编必改项或核心读者侧必改项，停止流程，不继续强行发布。

必须输出：

```text
06_修订与发布/三轮失败报告.md
```

失败报告需说明：

1. 哪些问题反复未解决；
2. 问题属于事实、方向、结构、文风还是读者体验；
3. 是否需要退回上游；
4. 是否建议放弃当前稿件路线。

---

## 六、主编审稿优先级

主编判断优先级：

```text
投资合规安全 > 事实安全 > 主承诺兑现 > 结构闭环 > 读者体验 > 文风一致 > 表达细节
```

如果投资合规或事实不成立，不得只做语言润色。

---

## 七、读者审读优先级

读者审读优先级：

```text
第一眼是否想读 > 是否看懂问题 > 是否跟得上机制 > 是否有获得感 > 是否愿意转述
```

读者审读不得替代主编审稿，不做事实判定，不决定是否发布。

---

## 八、发布前自检

发布前必须确认：

```text
[ ] 事实核查清单无阻断项
[ ] 主编必改项已闭环
[ ] 读者侧必改项已处理或被主编明确驳回
[ ] 密度审读侧问题已处理
[ ] 自由审读侧卡点已处理
[ ] 成稿卫生 H1 无命中
[ ] 文章主承诺被正文兑现
[ ] 标题承诺没有超出正文
[ ] 结尾没有过度升维
[ ] 文风禁用清单无明显违规
[ ] 投资合规红线无命中
[ ] 发布检查允许进入后续阶段
[ ] 成稿终审（format-final-check）已通过，可进 html-build
```
