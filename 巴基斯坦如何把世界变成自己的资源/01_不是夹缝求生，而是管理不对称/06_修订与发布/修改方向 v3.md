## 一、三条用户反馈（按优先级）

### 反馈 1：字数不做限制，先把事情讲清楚

**含义**：撤掉"3200-4000 / 4000-4500"等字数上下限。手机阅读节奏（段 ≤ 6 行、引言短句化、关键短句数量）**仍然有效**——因为是手机屏幕硬约束；但"字数不足"不再作为扣分项。

**意味着**：
- 宁可写到 4500-5500 字把论点铺开，也不要为了凑 3200 数字做"列数据 + 短句判断"的复述
- 不再以"字数"判断密度合格，**改以"判断密度"判断**——每段是否给出归因 / 机制 / 反预期 / 推演
- 加粗、表格、列表、过渡句、节末小结——这些**是服务于说清楚的工具，不是字数填充**

### 反馈 2：以观点为核心，新闻为论据

**含义**：当前稿问题不是事实少，是**判断少**。每段都在罗列"X 给了 Y / Z 发生了 W"，但极少段落给出"为什么 X 给 Y 能解决 Z / W 暴露了 V 这种结构性根源"。

**意味着**：
- 数字 / 事件 / 时间点**不能**是段落的终点，必须是**论据**
- 每个论据段必须紧跟 1 句**观点 / 归因 / 推演**——如果一段只列数字不判断，这段要改写或合并
- 机制判断要"敢讲"——比如"沙特存款续作 3 次 = 沙特不愿撤资但不愿增资" / "60 亿合同里只剩 16.5 亿 = 巴方对国际货币基金组织谈判力不足"——这是**作者观点**，不是新闻事实
- "巴基斯坦的兑换术是同时管理三组不对称依赖"——这句母观点已成立，但**还没在各节显形**——每个数字段都需要把它显形出来

### 反馈 3：脉络写清楚、写透彻

**含义**：当前稿脉络是"4 时刻 → 分工联盟 → 中国 → 海湾 → 美国 → 5 证换生存难换转型"，但读者读完只能记住"有 3 组不对称依赖"和"换生存难换转型"两句话。**整篇文章的"为什么是这样"链条没贯通**。

**意味着**：
- 每个节段不能独立讲自己的故事——必须**承接上一节、给下一节铺路**
- 节与节之间必须有**归因 / 推演 / 反预期**的桥段——不是"再看海湾"这种纯方位词过渡
- 主承诺"同时管理三组不对称依赖"必须在每一节**显形为不同的子机制**——比如：
  - §一 4 时刻显形"三组约束同时被激活"（已实现）
  - §二 显形"为什么是分工联盟"——巴方没有统一谈判主体，所以能把三组依赖拆给三家（机制解释）
  - §三 中国显形"为什么中国能承担耐心轴"——因为中国不指望巴方短期还钱，能给 30 年展期（机制解释）
  - §四 海湾显形"为什么海湾只补现金流不补合法性"——因为海湾资本要避险、要能源、宗派，不是慈善（机制解释）
  - §五 美国显形"为什么美国扣钱不扣合法性"——因为美国要的是合作条件不是还钱（阀门机制）
  - §六 显形"为什么 5 个工具都换不到国内改革"——因为既得利益网络是内生分配体系（机制归因）

## 三、新版 density-edit 评估标准

### 字数统计口径（用户 2026-06-22 第二轮反馈）

**字数一律以 `scripts/count_paragraph_chars.py` 输出为准**——`python scripts/count_paragraph_chars.py <file.md> --max 220`

该脚本统计的是：
- 段落级字符数（**不含空白**，即中文汉字+英文+数字+中文标点，不含空格/换行/Markdown 标记）
- 默认阈值 220 字/段（手机段落硬约束）

输出关键字段：
- **正文段落数**
- **正文段落总字符数（不含空白）** = 视为"全文字数"
- **单段超阈段落列表**（每段行号 + 字数 + 前 80 字预览）

**禁止**使用其他任何方式统计字数（如 Markdown 字符总数、汉字+标点估算、subagent 自行估算等）——一律以本脚本输出为准。Python 解释器用 `C:\Software\miniconda\python.exe`（已加入用户 PATH，直接 `python` 即可）。

### 4 维评估标准

每节从 4 维评分，**不再以"全文字数是否在 3200-4000"计**：

| 维度 | 通过标准 | 不通过表现 |
|---|---|---|
| **判断密度** | 每节至少 3 句机制归因 / 反预期 / 推演判断句（非数据复述） | 一段数字 / 事件后无归因，仅"X 给了 Y"型事实复述 |
| **脉络衔接** | 节首承接上节归因、节末铺路下节机制（用 1-2 句过渡） | 纯方位过渡（"再看海湾"）/ 纯复述（"4 个时刻不是巧合"） |
| **观点显形** | 节内至少 1 次显形主承诺（"管理三组不对称依赖"在该节的具体子机制） | 节内只讲自己的故事、不显形主承诺子机制 |
| **手机节奏** | 段落 ≤ 220 字（脚本阈值）；引言 ≤ 35 字 / 句；20-35 字中句不超过 3 句 | 段落超 220 字 / 引言有长句 |

**密度判断**：
- **合格**：4 维全过
- **需修订（小修）**：1-2 维未过
- **需大改**：3-4 维未过 / 出现"事实墙"（连续 3 段无归因）

**单段超阈（> 220 字）处理**：
- 不做硬扣分——但应标注"该段含多个判断，可考虑拆为 2 段让手机阅读更舒适"
- 4 证分工联盟段（§二 P12）和 FATF 翻译段（§五 P35）属于"机制解释必须放一起"的情况，**允许超阈**

**字数软观察（仅作提示，不做扣分）**：
- 如果某节段落总字符数 < 200（按脚本输出），提示"可能论点没铺开"——但不是必改
- 如果某节段落总字符数 > 1500，提示"可能堆数据未归因"——但不是必改
