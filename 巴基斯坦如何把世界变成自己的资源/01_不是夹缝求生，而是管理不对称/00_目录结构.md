## 二、每个文件职责

### 0.1 项目初始化（本阶段）

- `README.md`：项目入口，提供文章定位、核心问题、暂定核心判断、写作方向、文风要求、文件结构、执行原则、当前状态。
- `总计划.md`：项目计划书，提供目标读者、总目标、核心问题、暂定逻辑链、写作边界、证据缺口、文风原则、审稿机制、流程、最终交付标准。
- `00_目录结构.md`：本文件，提供完整目录、文件职责、命名规则、阶段推进顺序。

### 1. 资料阶段

- `01_资料/资料.md`（1.1 source-research）：本篇所需的原始资料、外部研究、官方口径、新闻报道、关键数字与年份；按"中国 / 美国 / 海湾 / IMF / 区域安全 / 国内权力"分类整理；明确待补资料。
- `01_资料/证据台账.md`（1.2 evidence-ledger）：将 `资料.md` 拆为 P0 / P1 / P2 事实主张，每条标注来源、风险等级、核验状态、推荐措辞。
- `01_资料/事实核查清单.md`（1.3 fact-check）：对每条事实主张做最终核验，标注"通过 / 待补 / 降级 / 撤稿"，并决定是否进入大纲与正文。

### 2. 洞察与方向阶段

- `02_洞察及主题/外部内容搜索.md`（2.1 ecosystem-scan）：检索外部相似选题，归纳常见角度、标题模式、过度使用的框架、差异化约束。
- `02_洞察及主题/洞察及主题初选.md`（2.2 insight-select）：基于资料、证据台账、外部扫描结果，生成候选洞察与主题方向。
- `02_洞察及主题/传播学审查卡.md` / `传播学分析卡.md` / `结构命题审查卡.md` / `结构命题分析卡.md`（2.3）：对候选洞察与结构命题做评分与筛选。
- `02_洞察及主题/方向把控.md`（2.4 direction-decide）：整合传播学、结构命题、读者契合度、事实边界、系列定位，输出本篇最终方向。

### 3. 文风与大纲阶段

- `03_文风与大纲/文风卡.md`（3.1 style-guide）：本篇专属文风卡，提炼自系列四份配置与本篇方向把控。
- `03_文风与大纲/读者审稿卡.md`（3.2 reader-criteria）：本篇读者侧审稿维度。
- `03_文风与大纲/大纲.md`（3.3 outline-plan）：本篇大纲，4-7 节结构 + 承诺链 + 小标题路标 + 每节职责。
- `03_文风与大纲/自由审读_大纲.md`（3.4 free-review）：大纲阶段的零上下文自由审读。
- `03_文风与大纲/大纲审阅.md`（3.5 outline-review）：大纲合规性审阅（方向、洞察角色、承诺链、事实边界、文风合规性、读者契合度、是否可进入草稿）。

### 4. 草稿阶段

- `04_草稿/草稿.md`（4.1 draft-write）：本篇第一版完整正文，严格按大纲、文风卡、事实边界、证据台账写作。

### 5. 审阅阶段（阶段 A 与阶段 B）

- 阶段 A：草稿完成后，并行触发
  - `05_审阅/自由审读_草稿.md`（5.1 free-review 零上下文自由审读）
  - `05_审阅/读者审读 v1.md`（5.1 reader-review）
  - `05_审阅/内容密度审读 v1.md`（5.1 density-edit）
- 主编阶段 A：
  - `05_审阅/主编修改建议 v1.md`（5.1 editor-review 整合三方意见，输出主编修改建议）
- 阶段 A 修订：交回 06-draft-revise 生成 `06_修订与发布/修订稿 v1.md`，按需重新进入 A 小循环。
- 阶段 B：以"主编修改建议 阶段B vN"驱动 `06_修订与发布/修订稿 vN.md`（N=1..5），每版同步触发：
  - `05_审阅/读者审读 阶段B vN.md`
  - `05_审阅/内容密度审读 阶段B vN.md`
  - `05_审阅/自由审读_修订稿 阶段B vN.md`
  - `05_审阅/主编修改建议 阶段B vN.md`
- 每轮 N 由主编根据审稿结论递增或终止；若任一硬约束（三红线、承诺链、单篇独立）不通过，必须打回。

### 6. 修订与发布阶段

- `06_修订与发布/修订稿 vN.md`：阶段 A / 阶段 B 修订稿正本（正文主体）。
- `06_修订与发布/发布检查.md`（6.1 release-check）：在主编明确"内容冻结"后执行内容闭环检查（修订完成度、事实安全、方向承诺、标题-边界就绪）。
- `06_修订与发布/成稿终审.md`（6.2 format-final-check）：HTML 前的格式与卫生终审（编辑痕迹、meta 污染、字数、加粗使用、HTML 可读性）。
- `06_修订与发布/人工介入报告.md`：阶段内任何人工介入判断的留痕（按需生成）。

### 7. 标题阶段

- `07_传播终审与标题/标题生态搜索.md`（7.1 title-ecosystem）：同主题标题生态分析。
- `07_传播终审与标题/标题方案.md`（7.2 title-write）：方法驱动的标题方案。

### 8. 插图阶段

- `08_插图/插图方案.md`（8.1 illustration-plan）：插图清单与分工。
- `08_插图/prompts.json`：配套 prompt 集。
- `08_插图/插图审查卡.md`：插图审查卡。
- `08_插图/images/`：图片资源目录。

### 9. 终稿阶段

- `09_终稿/01_终稿.html`（9.1 html-build）：本篇最终 HTML，仅做排版与格式实现，不重写正文。

## 三、文件使用规则

1. **命名**：所有文件名严格遵循上方目录结构，禁止使用空格、中文标点替代下划线；版本号使用 `v1`、`v2` 等，从 1 开始。
2. **正文文件**：所有正文文件（草稿 / 修订稿 / 终稿）必须包含承诺链自检（标题-引言-正文-结尾）。
3. **审稿文件**：所有审稿文件必须明确指出"通过 / 待改 / 打回"，并标注对应小节或行段；不得只写印象。
4. **证据文件**：`证据台账.md` 与 `事实核查清单.md` 必须包含来源、口径、风险等级；任何 2025-2026 局势必须标注"刷新节点"。
5. **HTML 阶段禁止重写正文**：HTML 阶段只做排版与格式实现；任何对正文文本的修改必须先回到 `修订稿 vN`。
6. **不引用其他文章**：本篇不引用系列其他文章的事实、机制、标题、结构；不引用其他项目、其他历史对话。
7. **不引入未核事实**：所有关键数字、年份、机构必须先入 `证据台账.md`，再进入大纲与正文。
8. **三红线自检贯穿全程**：英文字符 = 0；把多因素写成唯一原因 = 0；阴谋论与扁平标签 = 0。

### 硬约束（任一不通过则打回）

1. **三红线自检**：英文字符 = 0；把多因素写成唯一原因 = 0；阴谋论与扁平标签 = 0。
2. **承诺链闭合**：标题承诺 → 引言问题 → 小节推进 → 结尾回收 不脱节。
3. **单篇独立成立**：不依赖读者读过同系列其他文章。
4. **三层棋局定位**：本篇必须显式点出自己属于"国内权力结构 / 区域安全结构 / 外部资源结构"中的哪一层。
5. **平台可读性**：段落 1-4 行、最长不超过 6 行；每 600-1000 字一个小标题；前 300 字出现核心问题，前 500 字出现主承诺。
6. **数据可追溯**：所有关键数字、年份、机构均来自证据台账 + 事实核查清单；2025-2026 局势标注口径与刷新节点。
