# 审稿政策配置

> 适用系列：巴基斯坦如何把世界变成自己的资源
> 用途：供大纲审阅、读者审读、主编审稿、修订、发布检查等 agent 统一审稿红线、退回条件和质量闸门。
> 核心原则：宁可退回上游，也不能让事实不稳、承诺不兑现、结构不闭环的稿件进入发布。

---

## 一、审稿总原则

本系列所有稿件必须同时满足：

1. 事实安全；
2. 方向明确（属于三层棋局中的哪一层）；
3. 主承诺能被正文兑现；
4. 结构链条闭合；
5. 读者能复述核心机制；
6. 文风符合系列基调；
7. 不越过事实核查边界；
8. 不用情绪、金句或"巴铁"等扁平标签掩盖论证不足。

一句话原则：

```text
审稿不是把文章改得更猛，而是确认它是否真的成立。
```

---

## 二、质量闸门

### 2.1 事实闸门

以下情况不得进入大纲、草稿、标题或发布阶段：

- P0 事实存在待核；
- 核心事实来源不足；
- 关键年份、数字、机构、人物存在冲突；
- 事实核查清单标注"不采用"的材料仍被使用；
- 待补资料被当作正文支点；
- 相关关系被写成因果关系；
- 多因素解释被写成唯一原因；
- 把 2025 印巴危机、2026 阿巴边境等高流动局势写成"定局"。

### 2.2 方向闸门

以下情况必须退回方向把控或上游分析：

- 文章不知道自己主要服务三层棋局中的哪一层；
- 主承诺过大，正文无法兑现；
- 方向把控中的放弃项被重新引入；
- 文章同时试图解释多个大问题；
- 结尾升维与正文主线不一致；
- 把巴基斯坦写成"亲中反美"或"全是巴铁"等单线叙事。

### 2.3 大纲闸门

以下情况不得进入草稿：

- 大纲没有清楚的承诺链；
- 每一节与主承诺关系不明；
- 只是资料顺序，不是论证顺序；
- 事实支点不足；
- 引言、正文、结尾不服务同一问题；
- 大纲审阅存在必改项但未处理。

### 2.4 审稿闸门

本系列审稿分三层，逐层递进。每层角色和判断点不同，但都围绕"主承诺是否被兑现"。


| 审稿角色 | 主要判断                                    | 阶段定位          |
| ---- | --------------------------------------- | ------------- |
| 自由审稿 | 零上下文盲审，只读被审对象正文；以普通读者身份自由表达读后反应、疑问、跳读冲动 | 前置盲审，先于正式审稿运行 |
| 读者审读 | 读者是否想读、能否看懂、是否掉线、能否复述                   | 正式审稿第一层       |
| 主编审稿 | 事实是否安全、方向是否成立、结构是否闭环、是否可发布              | 正式审稿第二层       |


自由审稿和正式审稿的边界：

- 自由审稿**只读**被审对象正文一个文件，**不读**任何系列配置、事实台账、文风卡、方向把控、之前审读意见；
- 自由审稿产物为**纯自由文本**，不设必改项、不设模板、不设优先级、不设评分表；
- 正式审稿（读者审读、主编审稿）**必须读取**对应自由审稿产物，并**逐条回应**；
- 正式审稿**不得**把自由审稿建议自动全部升级为必改项；自由审稿只是"普通读者的另一双眼睛"，不是更高优先级。

每轮修订后必须检查：

- 读者侧必改项是否处理；
- 主编必改项是否处理；
- 自由审稿中提到的疑问、跳读、卡顿是否被正式审稿回应；
- 未采纳意见是否有理由；
- 修订是否引入新风险。

### 2.5 自由审稿（前置盲审）

本系列正式审稿之前，必须先跑一次"自由审稿"（调用 `_工作流/03_subagents/05-free-review.md` 或 `.cursor/agents/free-review.md`），由一个**零上下文**的临时 subagent 只读被审对象正文，写一份纯自由文本审读意见。

**作用对象**：


| 审读对象     | 输入文件                 | 自由审稿产物                     |
| -------- | -------------------- | -------------------------- |
| 大纲       | `03_文风与大纲/大纲.md`     | `03_文风与大纲/自由审读_大纲.md`      |
| 首版草稿     | `04_草稿/草稿.md`        | `05_审阅/自由审读_草稿.md`         |
| 阶段 B 修订稿 | `06_修订与发布/修订稿 vN.md` | `05_审阅/自由审读_修订稿 阶段B vN.md` |


**运行规则**：

1. 只读被审对象正文一个文件；
2. 禁止读取 README、总计划、方向把控、文风卡、证据台账、事实核查清单、系列配置、其他审读意见、历史对话；
3. 不设必改项、不设模板、不设优先级、不设评分表；
4. 不做事实裁决；
5. 不重写正文、不生成修订稿、不替正式审阅者下结论；
6. 产物开头可加一行元信息（性质 + 下游），其余为自由文本。

**正式审稿的回应义务**：

- 大纲审阅（`03-outline-review`）必须读取 `自由审读_大纲.md` 并**逐条回应**；
- 主编审稿（`05-editor-review`）必须读取对应自由审稿产物并**逐条回应**；
- 正式审稿**不得**把自由审稿建议自动全部升级为必改项；自由审稿只是"普通读者的另一双眼睛"，不是更高优先级；
- 自由审稿中提到的疑问、跳读冲动、卡顿位置，应被正式审稿作为线索，但采纳与否由正式审稿独立判断。

**巴基斯坦系列特别提示**：

- 本系列涉及"巴铁""印巴世仇""伊斯兰世界"等情绪高敏词，自由审稿应特别注意这些位置是否让读者"被情绪带跑"而失去机制感；
- 涉及 2025 印巴危机、2026 阿巴边境等高度流动局势时，自由审稿应表达"作为普通读者对'还会上演什么'的预期"，但不做事实裁决。

### 2.6 发布闸门

发布检查未通过，不进入标题、插图和 HTML 阶段。

发布检查必须判断：

- 是否允许进入标题阶段；
- 标题可以承诺什么；
- 标题不能承诺什么；
- 是否允许进入插图和 HTML 阶段。

## 三、审稿红线

### 3.1 事实红线

禁止：

1. 编造史实；
2. 使用未经核查的关键事实；
3. 改写事实核查清单限定口径；
4. 把"可能""部分""倾向"写成确定结论；
5. 用单一案例证明普遍规律；
6. 用现代概念强行解释历史人物动机；
7. 把"巴方表述""印方表述""第三方研究"混为一谈。

### 3.2 结构红线

禁止：

1. 开头承诺一个问题，正文讲另一个问题；
2. 资料堆砌但没有机制链；
3. 故事推进压过机制解释；
4. 每节都精彩但整体不闭合；
5. 结尾拔高到正文没有证明的位置；
6. 把"巴铁""印巴世仇"等情绪词当作机制解释使用。

### 3.3 文风红线

禁止：

1. 阴谋论；
2. 控诉腔；
3. 短视频腔；
4. 论文腔；
5. AI 腔；
6. 翻译腔；
7. 过度绝对化；
8. 过度升维；
9. 借"反西方"或"反印度"立场代替结构解释。

### 3.4 标题红线

禁止标题：

1. 承诺正文没有证明的内容；
2. 放大事实核查清单限定口径；
3. 使用平台风险词；
4. 只靠悬念不说明主题；
5. 用抽象词替代具体入口；
6. 用"巴铁""恐怖主义国家"等扁平标签做钩子。

### 3.5 自由审稿边界

为保证自由审稿不变成"另一份正式审稿"，主 agent 与 subagent 都必须遵守以下边界：


| 边界  | 自由审稿应做         | 自由审稿不应做                    |
| --- | -------------- | -------------------------- |
| 范围  | 只读被审对象正文       | 读系列配置、事实台账、文风卡、方向把控、其他审读意见 |
| 输出  | 自由文本、自然语言      | 表格、必改/建议分级、评分表、模板          |
| 判断  | 表达读后反应、疑问、跳读冲动 | 做事实裁决、机制评价、是否可发布的判断        |
| 行动  | 提出"读者可能卡在哪"的位置 | 给出具体改写方案、修订指令              |
| 立场  | 模拟普通读者         | 模拟"主编""读者审读员""事实核查员"       |
| 优先级 | 不设             | 不设                         |


违反任一边界的自由审稿产物应被视作失效，正式审稿不得据此判断。

## 四、退回规则


| 问题类型          | 退回阶段               |
| ------------- | ------------------ |
| 缺事实、事实冲突、来源不足 | 事实补充 / 事实核查        |
| 主承诺过大、方向不清    | 方向把控               |
| 洞察组合不成立       | 洞察初选 / 传播分析 / 结构分析 |
| 大纲承诺链断裂       | 大纲规划               |
| 读者看不懂或明显掉线    | 读者标准 / 大纲 / 修订     |
| 主编必改项较多       | 修订                 |
| 修订三轮仍不通过      | 三轮失败报告             |
| 发布检查不通过       | 修订或指定上游阶段          |


---

## 五、三轮失败机制

审稿修订最多三轮。

如果第 3 轮后仍有主编必改项或核心读者侧必改项，停止流程，不继续强行发布。

必须输出：

```text
06_修订与发布/三轮失败报告.md
```

失败报告需说明：

1. 哪些问题反复未解决；
2. 问题属于事实、方向、结构、文风还是读者体验；
3. 是否需要退回上游；
4. 是否建议放弃当前稿件路线。

---

## 六、主编审稿优先级

主编判断优先级：

```text
事实安全 > 主承诺兑现 > 结构闭环 > 读者体验 > 文风一致 > 表达细节
```

如果事实或主承诺不成立，不得只做语言润色。

---

## 七、读者审读优先级

读者审读优先级：

```text
第一眼是否想读 > 是否看懂问题 > 是否跟得上机制 > 是否有获得感 > 是否愿意转述
```

读者审读不得替代主编审稿，不做事实判定，不决定是否发布。

---

## 八、发布前自检

发布前必须确认：

```text
[ ] 事实核查清单无阻断项
[ ] 主编必改项已闭环
[ ] 读者侧必改项已处理或被主编明确驳回
[ ] 自由审稿产物已生成（大纲 / 草稿 / 阶段 B 修订稿 对应位置）
[ ] 自由审稿中提到的疑问、跳读、卡顿已被正式审稿逐条回应
[ ] 正式审稿未把自由审稿建议自动全部升级为必改项
[ ] 文章主承诺被正文兑现
[ ] 标题承诺没有超出正文
[ ] 结尾没有过度升维
[ ] 文风禁用清单无明显违规
[ ] 未使用"巴铁""恐怖主义国家"等扁平标签替代机制
[ ] 2025-2026 局势部分标注口径与刷新节点
[ ] 小尾巴和相关文章合规
[ ] 发布检查允许进入后续阶段
```
