# 文章结构与格式配置

> 适用系列：美国如何从工业国变成金融国  
> 用途：供大纲、草稿、修订、发布检查和 HTML 阶段统一文章结构、Markdown 格式、手机阅读节奏和非正文模块。  
> 核心原则：结构服务机制解释，格式服务手机阅读。

---

## 一、标准文章结构

默认结构：

```text
标题
引言
正文 4-7 个小节
结尾
小尾巴（可选）
相关文章（可选）
```

每篇文章必须独立成立，不依赖读者读过前后篇。

---

## 二、引言规则

引言任务：把读者带进问题，不提前抛作者已经想明白的金句。

推荐“三层进入法”：

1. 普通认知：读者通常怎么理解这个题材；
2. 关键反转：本文真正要讲的不是表面故事，而是背后的机制；
3. 入口承诺：这个机制如何改变产业、金融、制度或人的命运。

引言长度建议：

```text
150-350 字
```

引言必须在前 300 字内让读者知道：

- 本文讲什么对象；
- 本文要解释什么问题；
- 本文不是普通历史流水账。

---

## 三、正文结构

### 3.1 小节数量

默认 4-7 个小节。

少于 4 个小节：容易论证不足。  
多于 7 个小节：容易散，除非文章很长且每节有明确推进。

### 3.2 每节职责

每节必须承担一个明确功能：

1. 提出问题；
2. 展开背景；
3. 拆解机制；
4. 解释转折；
5. 对比两种路径；
6. 回收主承诺；
7. 点出现实回声。

不允许出现只负责堆资料的小节。

### 3.3 承诺链

正文结构必须形成：

```text
标题承诺 → 引言问题 → 小节推进 → 结尾回收
```

每个小节都要能回答：

```text
这一节如何帮助证明本文主承诺？
```

---

## 四、小标题规则

### 4.1 推荐小标题

小标题应像路标，而不是目录标签。

推荐：

```text
为什么地方银行接不住铁路？
分期付款改变的不是价格，而是购买资格
清算所保护的不是市场，而是会员
```

### 4.2 不推荐小标题

不推荐：

```text
背景介绍
制度演变
影响分析
历史启示
总结
```

### 4.3 格式

Markdown 中使用二级标题或三级标题，保持层级稳定。

```markdown
## 一、【小标题】

### 1.1 【必要时使用】
```

不要层级过深。一般不超过三级标题。

---

## 五、段落与句子

### 5.1 段落

默认段落：1-4 行。

最长段落不超过 6 行。超过应拆分。

### 5.2 句子

- 一句话只推进一个判断；
- 避免连续多重从句；
- 避免英文式长定语；
- 多用“谁获得了什么入口”“谁承担了什么风险”“谁改变了什么规则”这类动作句。

---

## 六、事实与注释

本系列正文不默认使用学术脚注体。

事实处理优先级：

1. 正文用通俗语言解释事实；
2. 关键数字、年份、机构必须来自事实核查清单；
3. 不在正文堆出处；
4. 如需说明不确定性，直接在正文降低口径。

禁止：

- 把来源不稳的事实写成确定支点；
- 为了显得专业堆砌来源；
- 用注释替代正文解释。

---

## 七、结尾规则

结尾必须回收本文，不要写成全系列总论。

结尾建议完成：

1. 回收本篇机制；
2. 点出本篇属于六个入口中的哪个入口；
3. 给读者一句可带走的判断。

结尾不应：

- 突然升到文明兴衰；
- 情绪控诉；
- 强行预测；
- 复述全文摘要；
- 引入正文没有证明的新概念。

---

## 八、小尾巴规则

小尾巴可选。

如使用，应满足：

- 不侵入正文论证；
- 不补充新的核心事实；
- 不改变本文结论；
- 语气克制；
- 可用于提示系列关系或后续阅读。

不允许小尾巴承担正文没有完成的证明任务。

---

## 九、相关文章规则

相关文章可选。

原则：

1. 只推荐真实存在的已发布或已定稿文章；
2. 不虚构相关文章；
3. 不使用未完成文章作为已发布推荐；
4. 相关文章列表不应过长。

推荐格式：

```markdown
## 相关文章

- 【文章标题】
- 【文章标题】
```

如相关文章尚未确认，发布检查阶段应标注“待发布补充”。

---

## 十、Markdown 格式规则

允许：

- 标题；
- 引用块；
- 有序列表；
- 无序列表；
- 表格；
- 分割线。

慎用：

- 过多加粗；
- 过多引用块；
- 多层嵌套列表；
- 复杂表格。

禁止：

- 大量 emoji；
- 彩色符号堆叠；
- 未说明用途的 HTML 片段；
- 过度装饰。

---

## 十一、HTML 前置约束

进入 HTML 阶段前必须具备：

1. 最终修订稿；
2. 发布检查通过；
3. 标题方案完成；
4. 插图方案和图片路径确认；
5. 小尾巴和相关文章确认。

HTML 阶段不得重写正文，只做排版和格式实现。

---

## 十二、结构自检

```text
[ ] 标题、引言、正文、结尾是否服务同一主承诺？
[ ] 每节是否有明确推进功能？
[ ] 是否存在资料堆砌小节？
[ ] 小标题是否像路标？
[ ] 读者跳读小标题能否理解主线？
[ ] 结尾是否自然回收正文？
[ ] 小尾巴是否没有侵入正文论证？
[ ] 相关文章是否真实存在？
```
