## 二、文件职责

| 文件 | 职责 | 主要负责人 | 何时使用 |
|---|---|---|---|
| `README.md` | 说明本文定位、目录结构、关键边界 | 作者 | 全程 |
| `总计划.md` | 管理目标、流程、字数决策、行文逻辑、风险 | 作者 / 主编 | 全程 |
| `00_目录结构.md` | 固定文件夹结构，避免项目文件散落 | 作者 | 建项时 |
| `01_资料/资料.md` | 汇总资料来源、摘要、可用点、风险点 | 资料研究员 | 查资料阶段 |
| `01_资料/证据台账.md` | 管理正文可用事实钉子和核查状态 | 事实核查员 | 查资料、写稿、修订阶段 |
| `01_资料/事实核查清单.md` | 做初步和二次事实核查 | 事实核查员 | 写大纲前、改稿前 |
| `02_文风与大纲/文风卡.md` | 控制本文文风、叙事比例、压舱句和禁止事项 | 作者 / 主编 | 写大纲前、审稿时 |
| `02_文风与大纲/大纲.md` | 形成文章结构、段落任务和证据配置 | 作者 | 写草稿前 |
| `02_文风与大纲/大纲审阅.md` | 主编从选题、结构、文风、风险角度审大纲 | 主编 | 大纲完成后 |
| `03_草稿/草稿.md` | 第一版完整成文 | 作者 | 大纲通过后 |
| `04_审阅/读者视角审读.md` | 模拟普通公众号读者阅读体验 | 读者审读员 | 草稿完成后 |
| `04_审阅/主编修改建议.md` | 从主编角度提出结构、文风、风险建议 | 主编 | 读者审读后 |
| `05_修订与发布/修订稿.md` | 合并事实核查、读者审读、主编建议后的修订稿 | 作者 | 修改阶段 |
| `05_修订与发布/发布检查.md` | 发布前最终检查 | 作者 / 主编 | 发布前 |

---

## 三、文件使用规则

1. 所有资料、证据和稿件都必须留在本目录内。
2. 旧系列材料只引用，不在旧目录继续改稿。
3. 证据先入台账，再进入正文。
4. 文风先成卡，再写大纲。
5. 大纲先审阅，再写草稿。
6. 草稿先审读和核查，再形成修订稿。
7. 杰斐逊 / 汉密尔顿引文用 Founders Online 英文原文 + 自己翻译，二次核查标原文行号。
