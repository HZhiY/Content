# 目录约定

> 仓库文件夹与文件的命名规范
> 现有结构如有不符合本约定的，参见 [_看板/迁移计划.md](./迁移计划.md)

---

## 一、顶层结构

```
Content/
├── README.md                  ← 项目入口（必读）
├── _看板/                     ← 跨系列管理文档
│   ├── 看板.md
│   ├── 系列状态汇总.md
│   ├── 目录约定.md            ← 本文件
│   ├── 迁移计划.md
│   └── 迁移脚本.ps1
├── 复盘/                       ← 跨系列方法论 + 数据
├── <系列名>/                  ← 各系列根目录
```

**约定**：

- 顶层目录只有四类：`README.md`（项目入口）、`_看板/`（跨系列管理）、`复盘/`（跨系列方法论）、`<系列名>/`（具体系列）
- 任何跨系列文档（看板、约定、脚本、复盘）都必须放在根目录的对应文件夹里
- 系列名不带"系列"二字（详细见下文）

## 二、系列根目录结构

每个系列下统一使用以下结构：

```
<系列名>/
├── README.md                  ← 系列入口（必读）
├── _meta/                      ← 系列元信息（定位、方法论、进度）
│   ├── 定位简报.md            ← 或 "系列大纲.md"（按系列实际命名）
│   ├── 执行策略.md            ← 可选
│   ├── 内容创作方法论.md      ← 可选
│   └── 进度.md                ← 系列内详细进度
├── 选题池/                     ← 待写题目的大纲（未动笔）
│   └── 候选题目.md
├── 废弃/                       ← 废弃稿集中地
│   └── <日期>_旧标题.md
└── 文章/                       ← 实际文章（已发布 + 草稿中）
    ├── 01_<标题>/
    ├── 02_<标题>/
    └── ...
```

## 三、命名规则

### 3.1 顶层系列名

- 不带"系列"二字：✅ `中国历代政治得失` / ❌ `中国历代政治得失系列`
- 不带"集"或"专辑"等修饰词
- 与发布在头条上的系列简介名称一致

### 3.2 _meta/ 命名

- 统一为 `_meta/`（下划线前缀），不放其他命名
- 美国系列现有的 `_meta_美国金融资本与产业资本/` 是不规范命名，需改为 `_meta/`

### 3.3 文章编号

- **两位数字** 编号：`01`、`02`、...、`99`
- **字母后缀** 表示同主题多角度：`02a`、`02b`
- **特殊篇**（非主体编号）用 `特_` 前缀：`特_特朗普与资本之争`
- 编号顺序按发布顺序，候选篇不预先占号

### 3.4 文件夹名

格式：`<编号>_<标题>/`

- 编号和标题之间用**单下划线** `_` 分隔
- 标题用**最终发布标题**（跟数据记录里的标题一致）
- 不带 `/` 等路径分隔符
- 不带 `（）` 等半角符号
- 中文标点按发布标题原文保留

**示例**：

- ✅ `01_皇权与相权如何长期拉扯/`
- ✅ `02a_王安石和司马光斗了一辈子，斗的其实是同一道无解题/`
- ✅ `特_特朗普与资本之争/`
- ❌ `01_标题/` （无标题）
- ❌ `01  标题/` （空格分隔）

### 3.5 文件类型

单篇文章文件夹下，最多出现以下 4 类文件：

| 文件 | 作用 | 数量 |
|------|------|------|
| `大纲.md` | 选题确定时的结构骨架 | 0 或 1 |
| `草稿.md` | **唯一工作文件**，所有编辑都在这里 | 0 或 1 |
| `定稿.html` | 发布到头条用的版本（定稿后生成） | 0 或 1 |
| `配图/` | 可选子目录，存放配图 | 0 或 1 |

**关键规则**：

- **源文件一定是 `.md`**：所有写作、编辑、迭代都在 `草稿.md` 里完成
- **发布版是 `.html`**：定稿后从 `草稿.md` 转换得到 `定稿.html`，用于发布
- **`.md` 和 `.html` 不再共存为工作文件**：旧做法是 `.md` 和 `.html` 同时维护，现在禁止
- **不用 `index.html`**：容易跟博客根目录的 `index.html` 混淆

**示例**：

- ✅ `文章/02_标题/大纲.md`、`文章/02_标题/草稿.md`、`文章/02_标题/定稿.html`
- ❌ `文章/02_标题/index.html`（语义不清）
- ❌ `文章/02_标题/02_标题_初稿.md`（文件名重复主题名）

### 3.6 _meta/ 文件命名

每个系列的 `_meta/` 下文件命名保持灵活，但建议遵循以下约定：

| 文件 | 作用 |
|------|------|
| `定位简报.md` | 读者画像、系列定位、禁区、单篇结构 |
| `系列大纲.md` | 完整篇目列表（每个系列的"总目录"） |
| `执行策略.md` | 写作流程、验收标准 |
| `内容创作方法论.md` | 实战手册（选题、标题、结构、金句等） |
| `进度.md` | 系列内详细进度跟踪 |
| `原著.md` | 系列的原始素材出处（仅历史系列） |
| `主题池.md` | 候选主题列表 |

文件名不强制统一，按系列实际需要放，但**单系列内要保持一致**。

## 四、状态标记

在 `_meta/进度.md` 和各篇 `大纲.md` 中统一使用：

| 标记 | 含义 |
|------|------|
| ⬜ | 待开始（未列入任何文档） |
| 📝 | 选题已确定，大纲阶段 |
| 🔄 | 草稿中（草稿.md 存在但未发布） |
| ✅ | 已发布（数据已记录） |
| 🔥🔥🔥 | 数据表现最高（爆款潜力） |
| 🔥🔥 | 数据表现较高（稳定输出） |
| 🔥 | 数据表现中等（引流内容） |
| ⚠️ | 数据不稳定（需分析） |

## 五、跨文件引用规范

- 跨系列引用使用相对路径：`./日本金融系列/_meta/进度.md`
- 系列内引用使用相对路径：`./_meta/进度.md`
- README 里的引用必须用 markdown 链接格式：`[标题](./路径)`

## 六、git 提交规范（建议）

虽然这是个人项目，git 提交建议遵循：

- **feat: 新增文章** — 完成一篇新草稿或发布
- **refactor: 目录整理** — 目录结构、命名规范化
- **docs: 看板/约定更新** — 看板、目录约定、复盘文档更新
- **chore: 废弃稿归档** — 把不再用的稿子移到 废弃/

提交信息用中文，保持简短。

## 七、不允许的做法

以下做法在任何情况下都不允许：

- ❌ 在系列根目录直接放文章（必须放 `文章/` 下）
- ❌ 源文件用 `.html`、发布版用 `.md`（规则反过来）
- ❌ `index.html` 出现在文章文件夹里
- ❌ 同一篇文章有 `草稿.md` 和 `草稿.html` 同时维护
- ❌ 废弃稿混在主目录里
- ❌ `articles/`、`posts/`、`专栏/` 等与 `文章/` 同义但异名的目录
- ❌ `_meta_xxx/`、`_meta1/`、`meta/` 等与 `_meta/` 同义但异名的目录
