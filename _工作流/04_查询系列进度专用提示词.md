# 查询系列进度专用提示词（可复用模板）

> 适用于：当你需要让 AI 编程助手（或主 agent 的子会话）**只读不写**地核验某个长篇写作系列的进度。
> 用法：把模板中的 `【系列文件夹名】` 替换为实际系列名（例如 `中国历代政治得失`），整段发给代码助手即可。

---

## 模板正文（直接复制）

```text
## 任务：查询《【系列文件夹名】》系列当前写作进度

仅查询、不修改。把"权威进度"和"文件系统实况"对齐后，输出可核验报告。

### 权威源（按优先级使用）
1. `【系列文件夹名】/_meta/进度.md` —— 系列进度的"唯一真相"。
2. `【系列文件夹名】/` 顶层 `NN_xxx` / `NNa_xxx` 目录 —— 已建项目的物理列表。
3. 各项目文件夹下的 `README.md` / `总计划.md` / `00_目录结构.md` —— 单篇进度的最近一手记录。

### 执行步骤
1. 读权威源：打开 `_meta/进度.md`，记录"最后更新日期"、第一批/第二批进度表。
2. 扫文件系统：列出 `【系列文件夹名】/` 顶层所有 `NN_` / `NNa_` 开头的目录（排除 `_meta/`、`articles/`、`README.md`），按编号升序。
3. 比对差异：
   - 进度表标"已发出"，目录是否存在
   - 进度表未列、目录存在的"幽灵项目"
   - 进度表标"进行中"、目录存在并走到哪一步（看 `04_草稿/`、`06_修订与发布/` 是否非空）
4. 定位最近产物：取"进行中"项目里 mtime 最新的文件路径。

### 输出格式（严格按此）
## 《【系列文件夹名】》进度核验
**核对时间**：YYYY-MM-DD HH:MM
**权威源最后更新**：YYYY-MM-DD
**核对结论**：✅ 一致 / ⚠️ 存在 N 处差异

### 已发出篇目
| 编号 | 标题 | 进度表状态 | 文件系统状态 | 差异 |
| ... | | | | |

### 进行中篇目
| 编号 | 标题 | 当前阶段 | 最后修改文件 | mtime |
| ... | | | | |

### 差异清单（如有）
- 例：进度表未列但目录存在的项目 / 进度表标"已发出"但找不到对应目录

### 用户记忆核对（如用户给了预期编号）
- 你的记忆：第 X 篇/第 X 章
- 实际结果：✅ 正确 / ❌ 实际是第 X 篇

### 兜底
- 进度.md 不存在 → 立刻停止并报告，不猜。
- 同编号有多个目录（`01_xxx` + `01a_xxx`）→ 把 `a/b` 当作同一篇的变体一并列出。
- 严禁修改任何文件，只读不写。
- 不要"善意补全"——只报告事实。
```

## 模板填写示例（以《中国历代政治得失》为例）

将上方模板中的 `【系列文件夹名】` 全部替换为 `中国历代政治得失`，得到的就是本页初版的设计稿。

## 设计要点（为什么这么写）

- **路径优先于记忆**：工作流系列都有标准结构（`_meta/`、项目文件夹命名 `NN_xxx`），把路径写死比让助手"猜你想查哪"更稳。
- **三源对照**：权威源（进度.md）→ 物理源（目录列表）→ 单篇源（README/总计划）。三层互校验，能自动暴露"进度表与实际不一致"的偏差。
- **只读 + 兜底**：长跑几个月的写作项目里，进度核验是高频轻任务；写一个可复用的只读模板，避免每次重新发明轮子。
- **输出强结构**：固定表格 + 段落，助手按格式填字段即可，也方便你直接复制到日报/看板里。
