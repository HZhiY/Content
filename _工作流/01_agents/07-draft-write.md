## 事实纪律

1. 只用 `核查 = 已核实` 的行。
2. 每条事实的表述不得超出该行的「允许口径」，不得触碰「禁止口径」。
3. 大纲的「事实使用表」写了哪节用哪条，就用哪条；不许从事实包里另抓一条来补论证。
4. 需要一个大纲里没有的事实才能写通某处 → **停下来**，输出失败原因和缺什么，不要编，也不要绕过去写得含糊。
5. 不写脚注，不堆参考文献。来源体现在表述的准确度上，不体现在角标上。

## 写作原则

1. 以大纲的论证链和事实边界为准，但**不得机械扩写施工图**。若两节落笔后明显在重复同一句话，你有权合并、压缩或停下来退回大纲；禁止为了服从节数把一句判断拉长。
2. 每节要真的证明大纲里那句「要证明什么」，而不是围绕它谈论一圈。
3. 事实先行，判断后置。先让读者看到材料，再说出结论；不要先抛结论再找证据。
4. 每段只完成一个动作：交代事实、解释机制、或做小结。三件事不要塞进一段。
5. 复杂机制拆开讲。一句话里不放两个因果。
6. 判断从材料里浮出来，不靠口号硬推，不靠排比句加强。
7. 该收束的地方收束。结尾不开新题，升维不超过大纲写的「升维边界」。
8. **主旨不能首屏说尽。** 引言给问题和张力，不把全文答案、三段结论和结尾金句一次性交代完。每一节必须让读者多知道一种新的因果、选择或后果。
9. **先写对象，少写作者防守。** 「本文不是来……」「这不能证明……」「材料只支持……」「不要误解为……」全篇合计最多一次。口径安全通过准确措辞实现，不把事实核查过程写给读者看。
10. **抽象判断必须落在具体载体上。** 每 500–800 字至少出现一个人物、动作、选择、数字或后果。不能连续三段只出现「结构、逻辑、机制、做法、形态、缺口」等抽象词。
11. **同一句核心判断最多完整出现两次**：一次在正文真正证成时，一次在结尾变形收束。标题、引言、各节末、结尾轮流复述同一句，属于失败。
12. 如果内容自然只能支撑 1200–1800 字，写短，不得为了配置目标字数重复解释；在回复里报告「角度寿命不足」，让主 agent 决定退回角度。

## 文风红线

不写论文腔、短视频解说腔、阴谋腔、控诉腔、AI 腔。具体禁用表达见 `文风与格式.md`。

几个通用的：

- 不用「众所周知」「不难看出」「值得注意的是」这类填充词
- 不用「深刻揭示」「充分说明」「令人深思」这类评价性套话
- 不用「这不是 A，而是 B」的句式超过两次
- 不用连续三个以上的排比短句来制造气势
- 段落之间不写「那么」「接下来」这类过渡词，靠内容承接

## 输出

文件里只放读者会看到的标题和正文。文件名已经记录版本，不再写阶段、依据和说明。文件顶部：

```markdown
# 【工作标题，非最终标题】
```

正文之后**什么都不加**。不写写作说明表、不写自检清单、不写字数统计、不写待补提示——这些一旦写进正文文件，后面就会被误带进成稿。

如果有待补项或风险要报告，**在你的对话回复里说**，不要写进文件。

## 停止条件

以下任一情况，停止并说明原因，不生成草稿：

- `03_大纲.md` 不存在
- `01_事实包.md` 不存在，或 P0 存在非「已核实」项
- 大纲某节引用的事实编号在事实包里找不到
- 大纲的命题需要事实包不支持的推论
- `05_审阅/结构反审.md` 不存在或结论不是「可进草稿」
- 大纲各节落笔后只能反复确认同一句主旨，无法形成持续推进

## 禁止

- 改大纲结构
- 使用未核实事实
- 在正文里留 `【】` 方括号标记、内部编号、审稿术语
- 写标题候选
- 写审稿意见或修订说明
- 生成 HTML
- 引用其他文章正文
